## 已确定的产品决策

- 完整路线，首批细化并实施；第二、三批仅保留路线，不混入首批。
- 关闭窗口进入托盘；明确退出应用时停止所有工作台。不另建后台服务，不接管外部 CLI 进程。
- 全应用统一 DSH 版本，可安装并保留多个候选版本。
- 升级同时协调官方基础插件，第三方插件不自动升级。
- 支持恢复升级前快照；恢复前明确告知会撤销升级后的聊天与配置，并先保存当前状态。

- 不修改共享凭据和机器身份，不把会话隔离宣传为文件访问沙箱。

## 首批顺序与验收标准

### 1. 产品说明

更新 README 过时的竞品比较，参考 DSH-Launcher V3 已有多实例和内嵌界面的事实。区分应用更新与 DSH 更新，明确 web 基础插件升级的边界。同步 REQUIREMENTS.md 和 IMPLEMENTATION_PLAN.md；历史完成记录不得伪造为本次验收。

### 2. 配置读写与校验

保留 DSH 的 !!js 标签、用户配置、注释，不执行表达式；重复应用隔离配置不重复添加条目。准确按 row id 读取完整配置块，精确验证目标路径，不能从下一行配置误取 root。保留未知配置字段，配置覆盖须遵循 DSH 的实际整行替换语义。web 隔离 patch 禁写。原子落盘前备份。

已确认的实现问题：当前 js-yaml 默认 load 无法读取 !!js；extractRoot 按字符串切分后可能匹配后续 row。须选择能保留标签与注释的 YAML 文档解析方式并覆盖相关回归。

### 3. 进程生命周期

同一空间的启动、停止、重启串行；不同空间可并行启动且端口先预留。停止必须等待实际退出，处理启动中取消、spawn 错误、退出超时。先正常终止，有界等待后才强制结束本应用拥有的进程树。应用单实例，重复打开唤回现有窗口。不要杀外部进程，不把退出码或清理失败吞掉。

### 4. 诊断与配置恢复

从空间错误卡片和右键菜单进入诊断，展示失败阶段、退出信息、近期有上限的本地日志及下一步操作。消费工作台 stdout/stderr，避免管道阻塞；日志展示和复制需遮蔽凭据，不包含聊天正文、不自动上传。

按目标工作台列出配置备份并提供预览与恢复。先备份当前配置；旧备份若缺少隔离项，补齐本空间隔离项后验证。失败恢复操作前配置。配置恢复不恢复聊天、不修改 web 隔离 patch。

### 5. 托盘体验

关闭隐藏窗口，工作台继续运行；托盘包含显示窗口、空间状态、停止全部和退出。恢复窗口复用原有视图、选中状态及进程。明确退出等待全部所属进程结束。弃用旧 quitBehavior 中应用退出但遗留进程的语义，首次升级提示新行为。无托盘时关闭改为最小化，避免隐藏后无法找回。不自动恢复应用崩溃前的任务。

### 6. 运行时版本库

展示实际使用的版本及来源、已安装版本和候选版本。候选版本安装到独立目录，失败不改变当前入口。所有启动和插件命令统一使用选定版本，避免隐式回退到不同的系统 CLI。兼容识别当前托管安装和系统安装，不覆盖系统全局安装。应用更新与 DSH 升级在 UI 中分开。

### 7. 协调升级

1. 独立安装候选运行时，保留当前版本。
2. 预览所有受影响 profile（包括隐藏无界面 profile）、官方基础插件变化和兼容问题。
3. 用户发起后进入维护态，阻止新启动、创建、删除及插件变更，等待已有插件操作完成，停止工作台。
4. 确认退出后创建一致的升级前快照；快照失败终止升级。
5. 临时准备插件环境，只更新已使用的官方基础组合 dsh-base、dsh-web-app，保留第三方插件锁定版本、组合顺序和用户 patch。
6. 验证依赖解析、各 profile 配置、双 root 隔离和干净测试环境的 Web API 就绪；全部通过再提交插件环境和版本指针。
7. 提交失败恢复旧环境；成功后显示结果并保持工作台停止，由用户主动启动。

不得把静态预检声称为第三方插件全部兼容。测试不调用真实模型、不运行真实用户任务。升级尚未交还用户时允许自动回退；用户已使用新版后不得自动撤销新数据。

### 8. 快照与恢复

- 包含受管理 profile 的配置和可恢复依赖环境、默认 sessions/storages、Hub 工作台数据与元数据、全局设置、运行时版本信息。
- 凭据文件和机器身份文件不参与覆盖恢复；外部项目源码、Home 外部文件和外部服务状态不在恢复范围。
- 存放在会话扫描范围之外，区分所属 DSH_HOME；禁止递归备份快照自身。保留恢复所需依赖文件，断网也能恢复。
- 显示时间、版本、空间和影响。恢复采用整个快照覆盖，不合并新会话；显式确认后先生成当前状态快照，失败不覆盖。
- 不自动清理唯一可恢复版本。手动删除不可影响正在使用的快照。
- 升级和恢复持久化必要的操作阶段；中断后先执行恢复检查再允许启动。恢复完成后保持工作台停止。

2026-09-11 评审修复补充：恢复过程中的异常也必须经过恢复检查；存在未完成的替换、运行时切换或清理时，继续阻止启动和写操作。损坏运行时不能阻断设置与恢复入口。若当前运行时确实无法备份，只有用户在恢复确认中明确接受后，才保存标记为“仅数据备份”的当前数据，再应用完整快照；不得把这份备份宣称为可直接恢复的完整运行环境，也不得默认跳过备份。恢复完成后同步设置表单，保存时不能写回恢复前的草稿。

## 最小接口与一致性

沿用类型化 preload/IPC：空间诊断和日志订阅、配置备份列表与恢复、运行时清单与安装、升级预览与执行、快照列表/恢复/删除、维护状态事件。前端只传名称、版本和快照标识，主进程解析实际路径。所有相关写操作由主进程的维护互斥统一拦截，复用现有插件队列，避免嵌套入队死锁。进程状态与 Agent 任务状态不能混用。
