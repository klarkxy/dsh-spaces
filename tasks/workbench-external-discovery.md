# 外部 DSH 进程边界

> 现行边界说明。架构见 [../docs/architecture.md](../docs/architecture.md)，故障政策见 [../docs/let-it-crash.md](../docs/let-it-crash.md)。早期恢复、回滚和接管方案只作历史，不是现行要求。

## 结论

Supervisor 只能可靠管理自己启动并登记的 DSH 进程。用户手工运行、未安装受管桥接或从未由当前 Supervisor 启动的进程，不属于可发现、可停止、可删除或可收养的空间实例。

这不是一个可以通过扫描端口或进程列表可靠补齐的功能：同名 profile 可以存在于不同 Home，命令行通常不能证明进程的 canonical Home，端口和 HTTP 页面也不能提供足够的所有权证据。

## 当前语义

- 已登记但仍存活的遗留实例可以显示为外部或不可管理状态。
- 从未登记的手工进程对 Supervisor 不可见。
- `stopAll` 只停止所有权明确的受管子进程。
- 未登记进程不会被自动收养、强杀、重启或赋予管理权限。
- 普通空间成员资格仍只认注册项；发现进程不会创建空间成员资格。
- 没有把握时保留未知，不按名称、端口或 profile 文本猜测归属。

## 对备份和维护的影响

创建 Home 备份前会停止已知受管空间，但外部进程可能仍在写入主应用或其他数据。因此备份只能声称：

> 已知受管空间已经停止后取得的 Home 副本。

它不能声称所有潜在外部写者都已停止，也不能声称是整个 Home 的强一致性快照。快照恢复本来就不是现行产品能力，不得借外部进程问题重新引入恢复链。

维护操作只能使用自己拥有的停机列表。检测到无法证明归属的候选进程时，不得把它加入停机或删除计划。

## 禁止的补偿方式

- 按端口号反推 profile 或 Home。
- 把本机所有 DSH 进程视为当前 Home。
- 读取其他进程的完整环境、令牌或私有内存来识别归属。
- 交换或扫描外部实例的认证材料。
- 默认终止未知 PID。
- 为了让列表“完整”而收养外部 profile。
- 把会话写租约当作完整进程登记；没有活动写句柄的空闲进程可能不可见。

## 若需要更强保证

准确列出本 Home 的外部实例需要可证明的上游能力，例如包含 canonical Home、profile、进程身份和启动代次的原子实例登记。

会话写租约可以在特定维护场景证明“某个会话当前有写者”，但不能证明没有写者，也不能识别所有空闲进程。任何此类检查都必须是非占锁、只读并失败关闭，不能为了探测而取得官方写租约。

在上游能力不足时，产品应明确当前一致性范围，而不是用猜测补齐。现行架构不因此增加自动发现、自动接管或恢复功能。
