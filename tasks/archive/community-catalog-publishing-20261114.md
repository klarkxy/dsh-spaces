# 2026-11-14 公共插件目录与 npm 发布准备

用户接受“独立项目身份、作者保留各自 npm 包、公共目录开放贡献、仓库内手动发布”的方案，并授权实施。主包保留项目级 `@dsh-spaces/plugin`，未迁入 `@klarkxy`，未创建 npm 组织、扩大发布权限或实际发布。

## 实现

- `catalog/plugins.json` 是作者维护的贡献清单；构建读取 npm 元数据生成 `catalog/index.json`，同时供客户端默认远程目录和构建内置快照使用。删除原先独立的种子副本，避免维护两份信息。
- 首批 14 个插件来自 dsh-plugins。生成器接受其他 npm scope、无 scope 包和公开 HTTPS 源码仓库，不运行插件代码；不收录只有共享库能力、未声明 DSH bundle 的 npm 包。
- 双语卡片显示名称、作者、仓库与 DSH 范围。默认标注“已收录 · 兼容性未实测”；可选实测记录必须给出精确插件版本、DSH 版本、平台和公开证据。
- 用户可以直接按 npm 包名查询版本并预览安装，不要求先被目录收录。查询本身不写目录、不新增收录项；实际安装保持已有精确版本、计划及审批边界。
- 新增作者贡献说明、Issue 提交表单和目录校验 workflow。普通 PR、推送与目录收录不触发 npm 发布。
- `npm-publish.yml` 仅手动触发，默认 `publish=false`；依次复用 CI、插件打包，检查同次运行的实际 `.tgz` 后按明确选择发布一次。OIDC 只在发布 job 可用，未复用个人 npm Token。
- 发布后匿名读取元数据、下载 tarball 并核对完整性和渠道。发布失败、结果不确定及发布后核对失败分别留证，不覆盖版本、不自动重发。

## CI 与账号边界

上一轮远端 CI `43545432430` 失败，日志显示 Windows runner 的 `RUNNER~1` 短路径临时目录被真实路径检查拒绝，并影响日志与快照用例。本轮让两个 Windows CI job 和打包 job 共用经过 realpath 规范化的隔离目录与包缓存，不放宽产品路径守卫。

当前 npm 身份在受限和普通进程中均返回 HTTP 401，尚不能确认项目 scope 的发布权。首次发布需要 npm 账号授权以及包/Trusted Publisher 设置，原方案现归档于 [历史发布准备](../../docs/archive/npm-publishing-20261114.md)。本轮没有创建已发布记录，也没有将已有真实 Desktop 和长期运行待验项关闭。

后续远端 CI `43557518848` 已确认短路径问题消失，又暴露三个发布前差异：Node 24 不支持当前测试目录参数、英文系统下一个渲染断言错误地默认中文、标准安装创建空间时官方运行时缺少 `@deepseek-ai/cordis-plugin-group`。前两项分别改为明确测试文件清单、在断言内固定并还原语言环境。第三项通过两个全新目录对照确认：`legacy-peer-deps=true` 安装退出 0 但 CLI 导入失败，`false` 安装及 `--version` 均成功。独立运行时安装现在明确使用 `--legacy-peer-deps=false --include=peer`，不继承仓库开发安装例外；未对失败环境做重装、修复或重试。对照证据在 `.sandbox/runtime-peer-probe/`。

这些补丁完成列表检查、三组类型检查、LLM、蓝图、运行时/语言 59 项定向回归、重建与包预检；结果均通过（蓝图保留 4 个平台符号链接跳过项）。最终本机归档改为 `.sandbox/community-release-artifact-final/dsh-spaces-plugin-0.5.0.tgz`，SHA-256 `aa5707867fcf8403b4600373d5e8026eed8f5e4a71620370bde16f9ae449cfc3`，新发布入口只读检查通过。此前归档与失败 CI 记录保留，不混作最终制品。

CI `43558539626` 的 Node 26 全部检查通过；Node 24 暴露测试闸门目录在 worker 创建前被父进程写入的竞争，现由测试父进程准备目录并断言安装阶段确已开始，两个相关队列用例通过。真实安装已越过运行时缺依赖问题，后在“关闭 Web 后重新进入”失败：原脚本在 Windows 使用 `child.kill()`，跳过了官方正常退出和主空间 scope 注销，却将其当成正常关闭。验收现通过仅测试父进程持有的 IPC 调用官方 CLI 现有 SIGTERM 处理器，并等待退出码 0；不修改产品注册、更换服务纪元或增加恢复能力。
