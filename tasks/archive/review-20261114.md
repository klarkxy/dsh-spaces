- 子空间启动偏好此前随任意管理服务初始化执行。现在只由新的 Desktop 打开请求携带，并通过同一作业队列串行执行；Web 和确认式服务启动／重启不携带该偏好。
- 诊断日志订阅 `unhandledRejection` 改变了 Node 默认致命错误语义。改用 `uncaughtExceptionMonitor` 观察异常及致命拒绝，子进程测试确认仍以失败退出。
- Remote 传输错误及模型同步诊断曾直接记录原始异常。现在先对本次调用已知的 Cookie、启动令牌和模型 Key 脱敏再记录。
- 运行中模型路由采用深合并会保留旧的同名路由请求头等配置。改为官方 `settings/mutate` 的逐路由原子替换，保留目标独有路由，并检查实际读回值。
- 在线插件批次失败此前丢失前序成功项。作业现在记录每个目标的完成、失败和未执行状态，并保留已完成项的重启要求；结果条目上限与 256 个目标空间的边界一致。
- 停机插件操作成功后，打开的插件列表没有刷新；目录刷新也未覆盖空间详情入口。两个入口均已补齐。
- CI 和分发工作流使用开发日志级别构建，与新增包预检不一致。发布检查统一使用 npm 构建目标。
- 全量检查原先仍使用全局 npm/pnpm 缓存。本轮观察到全局缓存的 `EEXIST` 后，将两者纳入检查临时目录；同时修复队列测试未启用已有安装闸门造成的竞争。

## dsh-plugins 复用

默认目录直接读取 `https://klarkxy.github.io/dsh-plugins/plugins.json`。适配包名、精确版本、双语简介、用途与搜索标题；共享服务库不作为可安装 bundle 显示。自定义旧目录格式仍可读取。

内置快照来自站点 `generatedAt=2026-11-13T08:06:20.404Z`，包含 14 个插件/preset。逐项向 npm 官方源读取精确版本，14/14 包名、版本及 `dsh.bundle.patch` 声明匹配。此检查不等于每个插件已在 Spaces 内运行通过。

npm 查询保留 Spaces 现有的官方源／镜像选择、请求限制和失败处理，并补齐响应包身份、预先取消和分页截断时保留 `latest` 的检查。没有依赖 dsh-dev-index 内部的 `PluginRegistry`：它没有作为独立库导出，且自身仅使用固定官方 registry，与 Spaces 可选镜像的契约不同。

dsh-plugins 的发布脚本依赖 `plugins/*`、工作区依赖闭包、生命周期清单和该仓库的发布工作流，不能原样用于 Spaces 的内嵌 Supervisor/view-bridge 组件制品。其“冻结归档、校验完整性、发布后匿名下载核对”的流程可供将来发布采用；本轮保持 Spaces 现有打包及未发布候选状态。
