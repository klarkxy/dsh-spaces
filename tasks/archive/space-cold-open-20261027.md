# 首次打开空间：状态与耗时（2026-10-27）

用户要求首次打开不能提前显示绿点，同时缩短打开等待。本轮接续已打开空间的缓存切换优化。

## 行为

- Desktop 侧栏区分进程状态与本窗口页面就绪：停止／尚未打开为灰色，启动／打开中为黄色，收到当前运行代次的页面就绪确认后才为绿色，页面拒绝为红色。停止、崩溃、删除或运行代次变化使旧就绪记录失效。
- 用户明确打开停止空间时，认证展示页的准备与子空间启动并行。只提交一次启动；导航取消不会让迟到结果抢走当前页面，启动失败保留实际错误。
- 一次性认证入口直接跳到受认证的原生展示页，省去先加载普通首页再跳转。参数严格校验，原有单次消费、Origin、Cookie 和原生页鉴权保留。
- 原生展示页提前准备管理页面，且管理页面不再额外嵌入一份首页。Desktop 默认空间仍由官方宿主显示。Web 展示的首页保持原逻辑。

## 验证

- 定向测试 163/163 通过：状态顺序、并行准备、运行代次失效、HTTP 单次认证与输入拒绝、原生页面无重复首页、缓存切换及 Chromium 交互。
- 受限环境首轮 7 个浏览器测试因找不到该环境下的 Chromium 未能运行；改用已安装浏览器的普通进程后通过，原日志保留。
- 官方 Desktop 对比使用专用隔离 Home、userData、profile 和同一个停止的测试空间；未读取或更改真实 Home，未修改官方 SDK。每次测量均重新打开 Desktop，从点击空间到页面确认选中计时。
- 基线 12,271 ms；导航记录显示约 8.8 秒后才开始创建展示页，随后依次加载普通入口、原生入口、管理页面、额外首页和子空间页面。

- 优化后 8,628 ms，较该次基线缩短 3,643 ms（29.7%）。这是一次同机对比，不代表统计分位值；首次打开仍有真实子进程启动成本。展示页开始加载从约 8.8 秒提前至 1.4 秒，最终只有原生入口、管理页面、子空间页面三层，没有额外首页。
- 原生界面观察记录：0 ms 已停止；1,176 ms 启动中；6,847 ms 正在打开；8,165 ms 首次出现绿色且已选中页面。总计时包含自动化点击和确认的往返开销。页面出现官方预览版说明弹窗，已加载到子空间 UI；未测试模型调用。
- 原始自动化缓存切换计时为 2,090 ms（包含点击和跨进程观察开销），未据此宣称真实 Desktop 的瞬时切换延迟。
- 完整规定检查 14 组执行完毕，13 组通过（测试清单、三组类型、构建、spaces、workbench、recovery、LLM、blueprints、browser、包预检、Chromium）。默认测试中 1 项并行进程准备夹具提前退出，其余通过；失败用例单独核查 1/1 通过。未改实现、增加重试或覆盖首次失败，不能把这轮完整结果写成全绿。单独核查不能确定首次提前退出的根因。
- 最终隔离子空间和测试服务正常停止，端点已释放；官方程序与 app.asar 哈希和测试前一致。测量程序 exit 0。
