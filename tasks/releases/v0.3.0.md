# DSH Spaces 0.3.0

0.3.0 adopts the current [let it crash](../../docs/let-it-crash.md) product contract. Failed operations and crashed spaces keep their real failure state and report the known cause or explicit unknown. Spaces no longer offers automatic or manual recovery, rollback, repair, rescue-mode, or interrupted-job replay as product behavior.

Highlights:

- Reports workbench failures with space, stage, plugin, exit-code, and signal context when available, while keeping logs and copied details redacted.
- Uses terminal job states only: `succeeded`, `failed`, or `cancelled`; interrupted work is recorded as failed or unconfirmed and is not replayed.
- Makes Doctor diagnostic-only. Legacy recovery, rollback, restore, and resume product entry points return unsupported failures.
- Keeps plugin installation exact-versioned and surfaces download, install, start, and crash failures without silently switching to `latest`.
- Adds space export/import, templates, and first-failure batch semantics: completed items remain completed, the failed item remains failed, and later items are not run.
- Adds sample Cordis plugin fixtures covering independent plugin behavior, packed-tarball installation, crash reporting, and first-failure batch behavior.

Known limits:

- DSH CLI write compatibility is still explicitly verified for `0.1.5-rc.1` and `0.1.5-rc.2`; removing the permanent exact-version allowlist remains planned work.
- Unregistered DSH processes that were not started by the supervisor are still a known discovery gap.
- Catppuccin's original theme still fails when its own dependency is missing; Spaces reports that failure and does not replace or repair the theme.
- macOS and Linux packages are built by CI, but their runtime behavior is not locally verified in this Windows release pass.

The GitHub tag publishes desktop installers through the Release workflow. The `@dsh-spaces/*` packages are versioned with the release, but this tag does not publish them to npm.
