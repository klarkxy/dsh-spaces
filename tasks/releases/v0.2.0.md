# DSH Spaces 0.2.0 (historical note)

0.2.0 shipped isolation, diagnostics, a local plugin library, coordinated DSH version install, space start/stop/restart, and tray hide-to-background. Current policy is [let it crash](../../docs/let-it-crash.md): failures are reported; Spaces does not restore a failed environment.

What 0.2.0 **also contained then** (superseded, do not advertise):

- Coordinated upgrades that could apply a whole-Home snapshot and roll back after a committed switch.
- Diagnostics actions that restored configuration backups.
- A rescue / recovery page when the runtime was damaged.

Those are implementation facts of that build. They are not current capability and must not be copied into a later GitHub Release, community listing, or demo script.

Also in 0.2.0, and still valid to describe:

- Download plugins into a local library, then install them into selected spaces.
- DSH `0.1.5-rc.1` browser authentication and session APIs.
- macOS builds include the ZIP required by the updater.
- Workspaces isolate sessions and storage and share login identity. Session isolation is not a filesystem sandbox.

Windows installation, embedded DSH pages, isolated sessions, and (then) upgrades/snapshot recovery were tested with temporary data. macOS and Linux installers are built by CI; runtime behavior on those platforms was not tested in that release. Model generation and third-party plugin migrations were not exercised.
