## 2. 设计取舍

沿用讨论中的单后台方向，复用现有 Supervisor。它是 Spaces 管理状态的唯一业务执行者；DSH 自身写会话和用户手动运行 CLI 不属于这一承诺。

```text
桌面壳 / 浏览器 / 普通 DSH 插件入口
                  ↓
共享工作台组件与客户端（各入口保留权限差别）
                  ↓
受认证的管理 API → 现有 Supervisor
                  ↓
空间 / 插件 / LLM / 模板分享 / 运行时用例
                  ↓
现有文件布局、官方 DSH 接口、进程与制品适配
```

| 设计 | 合并后的处理 |
|---|---|
| 主线故障政策 | 保留错误、部分结果和中断证据；不自动或手动恢复、不重放、不回滚 |
| 全局 LLM | 保留 Home 连接库、凭据专用通道、空间 all/selected/none、本地配置和显式导入映射；不增加模型代理网关 |
| spaces-hub | 保留管理 profile 承载原生工作台，Host 只作受信任转接 |
| 普通 Spaces 插件 | 提供初始化与打开入口，不获得全 Home 管理权限 |
| view-bridge / llm-bridge | 分别承载视图协作与空间模型接入，保留权限隔离 |
| HomeController / 操作门禁 | 保留跨进程唯一运行权与进程内变更互斥；删除客户端之间交接业务控制权 |
| 存储与安装 | 保留磁盘布局、标准预构建插件安装；不换数据库、不迁整个 Home |
| UI | 共享组件、状态和业务客户端；iframe 与 WebContentsView 可保留为平台视图适配 |
| 恢复遗留 | 从新合同和可达链删除；旧调用由单一兼容边界明确拒绝，不删除用户备份和数据 |
| 快照 | 保留正常创建、查看、删除及 LLM 启动配置；不恢复历史环境，不按 snapshot 文件名批量删代码 |
| 制品分发 | 扩展现有清单统一 Supervisor、管理插件、view-bridge、llm-bridge、安装 worker；不建通用组件注册中心 |

实例使用当前服务所有者身份派生的 `serviceEpoch`，加上 `spaceId + generation`。复用已有所有者记录，不另建身份服务。公共错误保留结构化字段，文字展示交给 UI。

必须接受的行为变化：退出桌面后后台继续占用资源；Supervisor 不可用时所有管理入口不可用；崩溃残留锁可能阻止后续启动，更新切换后失败可能保持不可用。错误处理器不会启动替代服务或清锁。正常管理位置保留用户主动启停操作。

## 3. 生命周期与升级边界

| 场景 | 执行者与结果 |
|---|---|
| 首次初始化或正常启动服务 | 用户从受信任入口主动发起；启动器验证 Home、协议、制品；无持有者且无阻塞残留时启动一次 Supervisor，由其获取 Home 锁 |
| 第二个客户端打开 | 验证同一 Home、endpoint、协议与授权后连接现有健康服务；不重复启动 |
| 关窗口 / 关标签页 | 关闭视图；桌面继续采用隐藏到托盘（无托盘时提供可找回的行为）；任务与服务继续 |
| 退出桌面 | 销毁桌面视图与系统集成；不调用停止空间或服务 |
| 停止空间 / 停止服务 | 两个独立操作。停止服务先封闭新变更、处理已有任务并停止所属进程，成功后才释放运行权；忙碌及无法停止明确报告 |
| 服务失联、崩溃或旧控制器仍持锁 | 保留诊断和最后已知状态；拒绝变更，不清锁、不杀归属不明进程、不后台重连失败组件、不重发请求 |
| 用户重新打开界面 | 可以读取仍在运行的服务或已留存结果；不得把打开界面变成故障恢复流程 |
| 新旧协议相遇 | 可识别的兼容只读访问或明确版本拒绝；不得清锁、抢占或启动第二套旧/新执行器 |

主动停止服务必须有可访问的菜单/设置入口、范围说明、忙碌状态和失败反馈；不能只移除桌面退出时的清理代码。

组件更新采用一次有界交接，具体实现协议在 B1 固定、B5 验证：

1. Supervisor 下载并验证精确版本与摘要，将不可变制品准备到现有工具目录，记录不含秘密的更新计划；此时不改当前版本指针。
2. 用户确认停机后封闭新写入、等待当前操作到达可停止边界，停止所属空间和管理 profile。不能安全停止就报告失败，保留运行权，不进入切换。
3. 复用现有跨进程锁约束，给受信任的一次性启动器定义独占交接预约：绑定 Home、旧 epoch、制品摘要与交接标识。在旧服务释放运行权到新服务获取运行权之间，所有其他启动入口必须因预约而拒绝；不得出现无保护的切换窗口。预约中断只留证阻塞，不自动回收。
4. 启动器验证旧服务已退出及交接身份后，按预约取得独占切换权，原子切换选定制品，再仅启动一次新服务；新服务验证交接并取得正常运行权。启动器只管理程序版本指针和本次交接，不执行空间、插件或模型业务。具体锁的移交过程必须用竞争测试证明无双写窗口后才能实施。
5. 更新记录区分准备、停机、切换、启动的结果，后台退出后的错误写到有界、脱敏的启动器回执。提交前失败保持原指针；提交后失败保留现场，不回切、不再次启动。新服务不续跑旧 job。

此处的交接是受用户授权的正常升级流程。不得扩展成常驻启动守护、跨崩溃恢复状态机或故障对账器。已有 payload/锁足够时复用；若需要更重的新服务或存储层，须重新做架构适配审查。

### A2：只连接历史

满足 A1 后，在集成分支执行 `git merge --no-ff -s ours <已审计的旧分支完整SHA>`。这一步只连接父提交，不再改变代码树。不要使用 `-X ours` 代替，它仍会接入无冲突的旧改动。

核对 merge 前后 tree 完全相同、merge 的第二父提交是审计 SHA、旧 SHA 已是集成分支祖先。保存结果到验收记录。该步骤不是架构完成；后续 B 的提交继续沿这条历史推进。

最终并入 main 必须保留祖先关系：快进或保留 merge commit，禁止 squash/rebase merge 丢掉历史连接。执行合并与创建提交属于后续实施；推送、发布、删除远端旧分支需显式授权。

### B1：固定协议、权限与迁移合同

范围：`src/shared/workbench.ts`、`spaces-control.ts`、LLM 合同、插件 Remote/schema、preload/IPC 合同、`tasks/workbench-contract.md`。

- 定义协议版本、服务 epoch、空间 generation、状态版本与能力信息；分开服务可用性、空间状态、job 结果。旧预览和旧视图消息必须可拒绝。
- 新协议移除 controller.acquire/release 和恢复命令。服务停止是独立明确命令；旧客户端的兼容拒绝放在单一边界，停止维护两套有效业务合同。
- 正常轻操作直接提交版本条件；删除数据、批量变更、切换运行时使用服务端预览与执行前再校验。先串行变更，不增加通用并行调度器。
- requestId 与无秘密参数指纹绑定：重复请求读取同一 job，同 ID 不同参数拒绝；重启后旧任务只留结果/未确认信息，不执行。不可取消阶段明确返回无法取消。
- 凭据继续走专用接口，持久化无秘密回执，不能序列化到通用 job、分享或日志。后台授权与管理互斥不能因通道独立而绕开。
- 为旧持久化 jobs/plans/endpoint 定义只读识别或拒绝规则；损坏与未知格式保留原字节，不静默重置为干净环境。
- 固定第 3 节生命周期和升级独占交接协议及验证场景。

完成条件：合同/schema/兼容策略一致，新增客户端不能调用旧恢复/接管能力；两个客户端的过期版本和越权请求有明确拒绝结果。

范围：`src/core/application`、`src/adapters/node`、现存 `src/main` 业务模块。先形成清楚的依赖边界，再逐文件移动，不按目录整包重写。

范围：现有 `space-share.ts`、`space-share-zip.ts`、`space-templates.ts`、批量/插件模块及统一 API。迁移现有行为，不另写第二套导入器。

| 必须保留的能力 | 两端共同验收结果 |

| 空间创建、排序、命名、图标、正常启停及删除预览 | 相同数据、状态、错误和保护条件 |
| 插件发现、下载、多版本缓存、安装、移除、状态查看 | 区分目录、制品和实际安装结果；真实版本未知就显示未知 |

### B4：共享工作台并退出旧桌面后台

范围：`packages/plugin/src/workbench`、`src/renderer`、`src/preload`、桌面 adapters、`src/main/index.ts`、托盘与视图管理。按本次用户指示，前端实现交给 Agent Bridge Grok，使用 CLI 默认配置；主 Agent 控制共享协议和验收。

复用工作台组件、状态和业务客户端；桌面保留窗口、托盘、系统对话框、视图承载和受信任服务连接。删除 `desktop-llm` 执行分支及 registry/process/runtime/upgrade 业务装配；旧 `SpacesControlApi` 退出或成为有期限、无写逻辑的兼容转发。

恢复错误只留详情、日志和脱敏复制；正常管理操作放回正常位置。退出桌面、停止空间、停止服务分别可操作。覆盖键盘标签、焦点、输入法、拖放和视图切换；不为共享页面扩大 preload 权限。

完成条件：静态调用检查与真实两端交互都证明没有桌面第二写者；关闭任一客户端不停止后台任务，停止服务不会影响归属不明的外部进程。

### B5：分发、升级与遗留清理

- 一份构建清单包含 Supervisor、管理插件、view-bridge、llm-bridge、安装 worker 的精确版本、来源、摘要、协议/能力要求及实际加载路径。桌面和标准插件入口消费同一组制品。

完成条件：在最终插件 tarball 和桌面安装位置验证资源、版本、摘要与实际启动；缺组件显式失败；服务升级的竞争、停机失败、切换后失败均无双写或自动回退。

### B6：最终验收与合入准备
