# 旧共享连接兼容合同

> 状态：2026-10-25 现行兼容合同。本文描述 Home 级共享连接库的**数据所有权、启动快照、秘密通道和旧空间语义**。它是 [现行架构](../architecture.md) §6.2 的展开。
> 定位：这是**兼容路径**。新普通空间默认走 [主空间继承](llm-main-inheritance.md)，不需要先创建共享连接。旧连接与旧空间继续受支持，且不因本文件而获得新能力。
> 入口（2026-10-27）：新建空间只提供“使用主空间模型”和“在此空间配置”。连接库在“设置 → 模型与连接 → 旧连接兼容设置”中按需展开；空间详情中的旧绑定表单也默认折叠。本次不改数据格式或执行迁移。
> 不在本文范围：主空间继承（见上）、本地与会话模型选择（见现行架构 §6.3）、设置界面收敛（见 [模型设置重订方案](model-settings-redesign-20261022.md)，未施工）。
> 故障政策以 [let it crash](../let-it-crash.md) 为唯一权威。
> 2026-10-25 修订：本文此前是一份施工计划（分阶段实施、拟新增模块与接口清单、强制验收矩阵）。施工阶段、拟新增清单与代码落点已移除；历史测量结果曾记录于兼容目录 global-llm-acceptance.md（已随库一并删除），那是 0.1.5-rc.2 的历史证据，不是当前版本认证。

## 1. 范围与作用域

"全局"限定为**一个 Spaces 控制的 Home**，不是整台机器，也不是所有 DSH 安装。

首版能力（仍受支持）：

- 连接目录的增删改查（显示名、协议、地址、模型目录），删除前做引用检查；
- 显式 API Key 认证；不支持用假 Key 绕过无认证路径；
- 对经核验的协议建立明确支持范围；
- 模型目录的手工录入与显式拉取，发现结果不覆盖现有目录；
- 全局默认、空间级默认与会话级显式选择三级区分；
- 空间绑定：使用全部共享连接 / 指定连接 / 不使用；本地连接不受该开关影响；
- 独立凭据存储、只写管理入口、宿主侧解析，不落入空间配置与任务日志；
- 保存状态与生效状态分开显示，不宣称虚假的"全部生效"；
- 分享包不含 Key，也不含本机可复用的秘密引用。

明确的非目标：

- 云同步、多用户权限系统、租户隔离、OS 级密钥沙箱、计费或额度池；
- 代理中转、全局并发调度、自动测速、后台周期探测、自动拉模型；
- 自动修复、旧配置恢复、连接失败后降级、运行中热切换、任意版本兼容；
- 合并同名供应商、自动收编已有连接、删除原配置或清理旧凭据。

"只在某空间显示某连接"是产品选择策略，不是同一 OS 用户之间的秘密隔离。

## 2. 数据所有权

| 数据 | 唯一权威位置 | 消费者 | 写入者 |
|---|---|---|---|
| 连接元信息、模型目录 | Home 级连接目录 | 已接入的空间 | 持有 Home 写权的管理端 |
| 全局默认模型 | Home 级连接目录 | 已接入的空间 | 持有 Home 写权的管理端 |
| 共享连接凭据 | Home 级独立凭据存储 | 空间宿主侧的受管凭据解析 | 专用只写凭据入口 |
| 空间绑定策略 | 该空间的模型策略 | 该空间的接入层 | 明确的管理变更 |
| 空间默认模型 | 该空间自己的设置 | 该空间 | 该空间设置 |
| 本地连接与本地凭据 | 该空间原有配置与凭据位置 | 该空间 | 该空间原有入口 |
| 会话模型 | 会话原有状态 | 原有 Agent / 会话层 | 会话操作 |
| 已生效版本 | 运行实例的观察状态 | 管理界面 | 启动与实例上报 |

约束：

- 连接 ID 永久稳定且不复用；显示名可重复，不承担路由身份。两个连接下相同的模型 ID 是不同目标，以（连接, 模型）区分。
- 全局默认必须指向启用且存在于目录中的模型，不能引用某个空间的本地连接。
- 未知目录结构版本拒绝读取，不退回旧版或空配置继续。
- 不新增每空间的 provider 副本、Key 副本或"同步后的完整设置文件"；共享路由只存在于运行时内存的受管层。

## 3. 启动快照与生效

- 每个接入空间在**启动时**读取连接目录与自己的策略，完成结构、引用、凭据存在性和适配器能力校验，然后冻结一份快照。
- 启动报告包含目录版本、策略版本、每条连接版本、适配器实际版本、错误或警告；不包含完整配置或凭据。
- 运行中保存全局配置只改变目标状态，界面显示"待重启"。首版不热切换、不自动重启、不中断在途请求。
- 停止的空间下次启动直接读取最新版本。
- 用户选择"应用到所选空间"时，其语义是正常的显式重启计划：拒绝活跃或状态未知的空间，不擅自中断；再次启动前仍执行通常的隔离和版本检查。
- 批量执行沿用仓库现行策略：成功的保留、失败即停止整批、未执行的标记为未执行；不继续、不重试、不撤销。
- 管理界面关闭或管理 profile 退出，不使已运行空间的直连请求改为经过一个不存在的代理。Supervisor 不可用时管理写入失败，不产生第二个写控制者。

### 3.1 密钥轮换

更新 Key 生成新的凭据记录，目录原子提交到新记录引用。旧快照继续持有旧记录引用，不允许旧端点与新 Key 混用。旧凭据不自动清理；删除是独立的显式管理操作，必须能证明没有运行实例使用，无法核验时明确说明不能完成核验。

停止或禁用某连接在首版是配置变更，不是即时供应商凭据撤销。页面必须显示仍使用旧快照的实例；需要阻止继续请求时，由用户显式停止对应空间。

## 4. 秘密通道

- 含 Key 的请求**不得**成为普通任务命令，因为任务存储会保留命令与规范化命令文本。
- 凭据走独立、认证的只写请求；请求体只在处理生命周期内存在，不写入任务、请求日志、错误对象、浏览器存储、URL、命令行或子进程环境。后台任务只接受已存在的、不透明的凭据记录 ID。
- 写入顺序：校验权限、版本、连接结构与引用 → 写入新的不可变凭据记录 → 确认记录可读 → 原子提交目录（唯一发布点）→ 返回脱敏结果与目录版本。
- 凭据写入失败则不发布连接；目录提交失败不改变原目录。已经写入但未被引用的记录必须如实记录，不添加跨重启修补器。
- 提交成功但响应丢失时结果可能未知；允许用不含秘密的操作标识查询是否已提交，不自动重发。
- 使用官方凭据文件格式与原子写工具，不自创加密协议。POSIX 校验 owner-only 权限；Windows 校验 ACL，不能只证明调用了权限设置就宣称完成隔离。不得把"按用户文件权限保护"写成"恶意插件看不到密钥"。

## 5. 旧空间与接入语义

- 没有策略文件的空间按既有默认解释处理；"不使用共享连接"需要显式记录。改变这个默认会迁移无文件的旧空间，不允许。
- 显式选择共享连接、显式选择不使用、以及新的来源策略是不同决定；切换来源是用户明确操作，不由另一项设置暗中改写。
- 旧空间的来源策略不被自动改写或迁移；缺失桥接的安装与既有桥接的版本对齐是不同事实，不能混为一谈。
- 显式目标失效时失败，不自动改用其他连接、不按显示名猜测。
- 损坏的目录或策略不被当作"没有配置"而自动启用其他路径。

## 6. 接入官方设置与凭据服务

- 共享连接进入官方设置的**受管 base 层**，不写入空间的本地用户层；空间自己的设置文件路径保持不变。
- 本地用户层不得出现共享路由的前缀；API 写入与外部文件修改都要验证，不只依赖界面隐藏。
- 对受管键的写入拒绝必须覆盖更新、替换、批量修改、官方设置界面以及外部文件重新加载，不能只在某个入口拦截。
- 受管凭据引用只从全局存储解析；受管引用不做环境变量兜底，缺失时明确失败，防止同名环境变量抢占。非受管引用与普通 OAuth 记录继续委托空间原有凭据来源。
- 空间侧的凭据写入不能修改全局记录；全局记录的枚举不泄漏不相关记录。
- 同一空间上下文只注册一个设置服务与一个对应的模型适配命名空间，不靠"碰巧覆盖"挂第二个实例。
- 共享来源的展示由 bridge 的脱敏接口提供，不改写官方描述符的秘密与权限契约。
- 缺所需官方适配器时明确报错，不自动安装。

## 7. 默认模型解析

```text
已有会话明确模型
  > 该空间本地用户层默认
  > 该空间引用且可用的全局默认
  > 原有组合默认（仅当全局默认未设置且本地未设置时）
```

- 显式配置的目标失效时报错，不把上述优先级当作"失败后换模型"规则。
- 全局默认不在当前空间的绑定范围内时返回明确诊断，要求选择空间默认；不私自改绑定范围或改选其他模型。
- "继承全局"通过移除本地显式默认实现，不在策略文件里再存一份默认。
- 一个选择整体修改 provider 与 model，拒绝只改半个目标造成意外混配。已有会话不批量重写历史，也不自动切换。

## 8. 引用、删除与分享

- 绑定、当前默认或活跃快照仍引用某连接时拒绝删除；使用"全部连接"的消费者也计入引用影响。
- 先提供"从正常设置中排除或解绑"再删除的明确操作顺序，不提供"强制删除并自动改成另一个模型"。
- 历史会话不自动重写。删除后保留最小、不可复用的标识墓碑，不保留秘密。继续历史会话时若原路由不存在，明确失败或要求重新选择模型，不能把显示名相同的新连接当旧连接。
- 分享空间时排除全局 Key、本地 Key、凭据记录、绝对路径、启动令牌和完整连接目录；全局连接 ID 仅在本 Home 有意义，不作为接收端可直接使用的引用。可以附无秘密的连接需求清单，导入时由接收端显式映射；未映射即明确不可用。

## 9. 管理与错误语义

- 全局目录、策略和凭据写入都检查当前 Home 控制权；复用既有锁协议，不另起第二套租约。只读管理端不能靠直接调用新入口绕过检查。
- 写入在 Home 写权下串行执行，提交前重新校验服务纪元、所有权与目标版本；使用持久化版本加"预期版本"做比较交换，不依赖浏览器本地版本或纯进程内计数器。
- 引用检查与目录/策略修改必须经过同一个受控串行边界，避免"刚检查没有引用、另一个请求立即绑定后再删除"的竞态。
- 错误包含阶段、相关空间或连接、已知原因或明确未知，不含秘密与对话。错误卡只提供详情与脱敏日志，正常配置与启停入口不变成修复向导。
- 沿用仓库既有错误类别：版本冲突、需要写所有权、配置无效、运行时不支持、协议不支持、缺适配器、模型不存在、连接被引用、受管路由只读、受管路由冲突、缺凭据、凭据写入失败、目录查询失败、空间忙碌、应用失败、结果未知。
- 全部失败路径都没有自动重试、回滚、重装、换模型或恢复向导。

## 10. 界面职责（兼容路径）

- 兼容区块只在确有旧资产或旧消费者时出现；没有旧资产时不作为新用户前置步骤展示。
- 连接列表展示：显示名、协议、脱敏端点、模型数量、认证状态、被多少空间使用、已保存版本、哪些空间待重启。认证状态不能仅因为存在一个引用就显示为已配置。
- "获取模型"与"测试请求"分开：前者成功只代表目录查询成功，后者才是本次生成测试，不承诺之后始终可用。
- 共享连接在空间设置里只读，并提供"在连接目录中管理"的入口；本地连接维持原有编辑能力。
- 共享连接失败不自动回退到同名本地连接。
- 不能只用样式隐藏官方控件；宿主设置与凭据层必须拒绝越界写入。

## 11. 目录查询与网络安全

- 模型目录查询通过官方适配器的公开能力进行；不支持的协议返回明确错误，不自造路径。已保存连接的凭据在宿主侧解析，浏览器不先读取 Key 再带回。
- 请求有总期限、响应字节上限与候选数量上限；超限必须标示截断或失败，不把部分结果称为全部模型。无后台重试。
- 允许显式配置 localhost 或局域网端点以支持本地模型，但普通空间视图无权发起任意查询；端点变更预览标明目标来源；禁止 URL userinfo 与秘密查询串。
- 目录查询默认不跟随跨来源重定向；适配器自身的重定向行为同样需要核验，不能只保护查询一侧。
- 连通性测试固定最小提示、输出上限与预算提示，并由用户确认；不拿聊天记录当测试数据，不发送周期性"健康探测"消耗 Key。

## 12. 退出与退役

- 全局资源退出使用时，停用各空间引用即可；默认不删除连接目录、凭据或用户本地连接。
- 卸载桥接组件时必须通过正常插件管理移除接入配置，不把模块缺失包装成自动卸载修复。
- 旧版本遇到不认识的共享结构应拒绝该能力，不自动清空配置。安装升级是普通操作，失败后保留现场，不构建回滚链。
- 运行中热更新不在现行范围；若将来引入，必须复用同一权威目录、连接版本、凭据版本与生效状态，并证明在途请求快照稳定、失败不回滚、缺失确认不报全局成功，且不新建第二份注册表或消息中转平台。
