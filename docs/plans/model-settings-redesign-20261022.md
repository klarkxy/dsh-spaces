# 模型与连接设置重订方案

> 状态：**完整重订尚未施工**。2026-10-27 仅按用户要求完成入口调整：新建空间只提供主空间模型和本空间配置；旧连接库及空间绑定收进默认折叠的“旧连接兼容设置”。用户确认没有旧空间，本次不做迁移。本文其余目标语义与未决项不代表已落地能力。现行数据面与所有权以 [现行架构](../architecture.md) §4 和 §6 为准；本文与现行架构冲突时以现行架构为准。
> 前置：[主空间继承与专用 LLM 委派合同](llm-main-inheritance.md)、[旧共享连接兼容合同](global-llm-connections.md)。
> 日期：2026-10-22 起草；2026-10-25 修订为纯方案（移除实施层证据与施工排期）。
> 故障政策以 [let it crash](../let-it-crash.md) 为唯一权威。

## 1. 结论

**在主空间配置一次模型，普通空间直接使用。只有需要独立配置或兼容旧连接时，才进入额外管理。**

问题不只是文字多：旧共享连接库和主空间继承混在同一张表单里，而表单不能准确表达继承关系、当前选择和运行中生效状态。重订必须同时修正信息结构和状态契约，不能只把旧表单折叠。

普通流程不再要求用户创建第二份共享连接、先"提升"为共享、选择绑定模式或执行泛化"应用"。保留认证、空间隔离、凭据归属、显式来源切换和正常生命周期边界；不加自动迁移、重试、回退、恢复或失败后重启。

## 2. 待收敛的问题（行为描述，不含实施细节）

| 问题 | 必须改变的行为 |
|---|---|
| 下拉框显示"无"，下方却显示已选本地模型 | 本地、主空间和旧目录使用明确的模型引用；当前选择必须准确展示 |
| 同一模型的两种表示 | 统一解析身份，不靠显示名或字符串拼接猜测同一模型 |
| "选择模型"控件不可操作 | 用真正可操作、且与保存行为一致的选择器 |
| 所谓"生效模型"没有反映主空间继承 | 区分已保存配置、运行中观察和主空间当前默认 |
| 保存共享策略会退出主空间继承 | 来源只在用户明确切换时改变，不能由另一项设置暗中改变 |
| 待重启只比较旧目录版本 | 按实际受影响配置与运行观察判断，信息不足就明确"无法确认" |
| "应用"实际是停止再启动空间 | 保存与正常重启分开，动作直接命名 |
| 同一个大面板混用两种页面上下文 | 全局管理与单空间设置各有职责，不共用整个业务表单 |

## 3. 页面职责

| 位置 | 负责什么 | 移除什么 |
|---|---|---|
| 全局"模型与连接" | 主空间模型状态、官方连接设置入口；确有旧资产时显示独立连接库入口 | 空间选择器、逐空间默认表单、导入空区块、常驻批量重启 |
| 空间详情 → 模型 | 本空间来源、默认选择、可用状态和必要的生效操作 | 其他空间管理、主空间凭据编辑 |
| 聊天模型选择器 | 当前会话跟随默认或固定模型、调用参数 | 默默修改空间默认、来源或共享目录 |
| 模板导入流程 | 仅处理该次导入携带的外部模型要求 | 面向所有用户的常驻映射系统 |

连接的权威保持在拥有者：主空间连接由官方主空间配置维护，本空间连接由该空间维护，旧目录由原目录维护。Spaces 不再复制一份主空间连接数据库。

"管理主空间模型"打开已有官方设置入口。仅在确认官方支持嵌入时嵌入同一份表单；不得依赖官方内部界面实现或修改官方 DOM，也不另造配置写入器。具体嵌入落点需要交互实测才能确定。

主空间默认继续使用官方默认模型概念；不增加同义的第二个"全局默认"。旧目录默认仅在兼容管理里显示，并明确其作用范围。

## 4. 模型来源与默认选择

来源和选择是两个不同决定：

1. **使用主空间模型**：普通空间默认。凭据留在主空间，调用走已授权链。
2. **仅此空间配置**：用于独立供应商、不同账户或插件需求，已有本地模型直接可选。
3. **独立连接库**：保留旧共享目录与旧空间的配置方式，有资产或主动选择时出现。

在已接入主空间的空间里，应能选择：跟随主空间默认、固定主空间某个可用模型，或直接使用已有本地模型。固定某个主空间模型不等于关闭主空间接入；不得要求先"提升为共享"。

"跟随主空间默认"必须真正取消本空间显式默认覆盖，而不是只改界面标签。固定模型保存后，解析与实际调用必须指向同一模型；会话手动选择不暗改空间设置。

模型身份区分来源及其稳定标识，不以相同名称或地址自动合并。不同协议的路由可以分组展示，但不同路由仍须可辨识。已选模型被移除时保留名称和不可用原因，不显示成"无"，不自动切换。

空间级继承授权继续有效。逐连接授权是另一项独立的安全能力，本轮不以过滤下拉框假装实现。

## 5. 目标界面

全局页：

```text
模型与连接

主空间模型
当前默认  Kimi K3 · Magpie
[管理主空间模型]

独立连接库 · 3 个连接，2 个空间使用
[管理连接库]
```

没有旧资产或消费者时不显示兼容区块；主动使用其他配置方式仍有次级入口。主空间不可用时展示真实原因，不能伪装为空连接或转用旧目录。

空间详情：

```text
模型

模型来源  主空间
默认模型  跟随主空间 · Kimi K3
[更改默认模型]  [更改模型来源]

本空间单独配置的连接  1 个
[管理此空间连接]
```

本地连接区只在确有资产或主动配置时出现。选模型时按来源分组，并显示实际可用状态。旧空间根据真实模式展示，不能统一标成主空间。

独立连接编辑使用紧凑表单：名称、协议、地址、认证、模型列表。去掉没有决策价值的四步向导拆分。显式获取模型与测试生成请求分开；手工录入保持可用，目录查询成功不能宣称生成可用。保存连接不擅自把第一个模型设为默认。

## 6. 目标保存与生效语义

| 操作 | 用户可见行为与边界 |
|---|---|
| 聊天切换已可用模型 | 后续请求使用所选模型；不附带空间重启，不改进行中的请求 |
| 跟随主空间默认 | 新请求解析主空间当前默认；已准备好的请求保持冻结目标 |
| 编辑主空间官方连接 | 服从官方实际加载行为，展示运行中观察；不能凭文件保存承诺热更新 |
| 更换来源或启用不同接入路径 | 保存后按真实运行路径显示是否需要正常重启；已停止空间显示"下次启动使用" |
| 修改旧目录连接 | 保存目录，只提示真正受影响且仍使用旧配置的运行空间 |
| 写子空间默认 | 必须补运行观察，验证即时生效或明确下次启动生效 |

按钮使用"保存"和"重新启动此空间"，不再使用泛化"应用"。需要重启时提示"已保存，重新启动后生效"，复用空间详情的正常生命周期操作。忙碌或活动未知时说明原因并拒绝，不排队、不自动等待后执行、不重试。

批量入口只用于旧目录编辑确实影响多个空间的情况，放在次级影响列表里，先列清对象；失败结果保留已完成、失败和未执行。无需受影响空间时不显示空重启表单。

## 7. 导入与旧连接兼容

模板没有模型要求：不增加选择或映射步骤。

模板确有外部要求：在导入过程中显示"为此模板选择模型"，允许选择已有主空间模型、本地连接、旧连接库，或明确"稍后配置"。后者必须显示相关模型尚不可用，但不强求所有插件调用成功才允许空间定义存在。

导入映射当前只接受旧共享引用，必须补真实来源契约；不能把主空间选择幕后复制成共享连接，也不能用前端映射假装已完成支持。导入后仍未解决的要求，放在对应空间详情就近提示，完成后消失。

旧配置处理：

- 不自动迁移、不复制凭据、不改写旧空间、不删除路由。
- 有旧共享绑定的空间继续读取、编辑及正常启动；仅打开设置不写策略。
- 用户主动更换来源时预览本空间的来源和默认变化，保留旧资产；切换不是删除。
- "提升为共享"移出普通页。保留确有消费者的一次性复制能力时，放到连接库的"从现有空间添加"，明确创建新连接、保留原连接及凭据授权；不称持续同步。
- 本轮不退役旧共享后端，既有界面、创建参数与运行快照仍是实际消费者。

## 8. 状态与可访问性

| 状态 | 必须表达 |
|---|---|
| 加载中 | 正在读取模型状态，不先闪现"无" |
| 未配置 | 明确缺少默认还是连接，并提供准确配置入口 |
| 读取或调用失败 | 就近展示真实失败及脱敏详情，不变成空列表 |
| 无权限 | 显示当前来源、状态和只读原因 |
| 已选模型不可用 | 保留选择身份与原因，不自动改选 |
| 已保存但未生效 | 区分持久化结果、运行中旧配置和下次启动；观察不全写"无法确认当前生效状态" |
| 保存失败 | 保留编辑草稿，显示失败，不伪造成功、不自动重试 |

选择控件须有真实可操作语义、关联标签、可见焦点和完整键盘行为。关闭选择器焦点回到触发按钮；保存状态和错误可被辅助技术读取；动画不能遮挡首帧错误。秘密不进入页面展示、日志和普通状态接口。

## 9. 本轮范围

这轮应交付完整流程，不能停在一个可运行的下拉框补丁：

1. 建立准确的模型状态契约：配置来源、持久化默认、运行中解析、可用性及待生效原因；复用现有主空间描述、授权与接入层，不另建模型注册中心。
2. 补齐主空间、本地与旧目录的选择与写入语义；来源切换显式独立，跟随模式清除必要的显式覆盖。
3. 全局页不再挂载整个空间绑定面板；把单空间选择、导入要求、旧目录管理和生效提示放回各自位置。
4. 完成导入引用契约、兼容入口、中英文文案和键盘交互。
5. 在有效计划中标明本方案范围，实现后再更新完成状态；在此之前不得把本文条目写成现行能力。

## 10. 验收场景（目标）

1. 截图中"已选本地模型却显示无"的矛盾消失；旧共享引用也能正确回显。
2. 新建普通空间直接使用主空间模型完成一次真实请求，没有新增共享连接或复制凭据。
3. 主空间默认变化后：跟随的请求更新、固定的模型保持、在途请求目标保持；空间默认与会话选择可分辨。
4. 本地模型直接可选，不经过提升；固定主空间模型不因选择而失去接入。
5. 全局普通页面没有空间选择器、导入空区块、常驻批量重启和第二套主空间默认。
6. 无模型要求的导入零额外步骤；有要求时主空间、旧目录与稍后配置都得到真实处理，未完成要求可在空间详情继续配置。
7. 旧目录空间仍能读取、编辑与正常重启；单纯打开设置不改数据；明确切换才改变来源与继承。
8. 主空间失联、无默认、权限不足、模型移除、读取失败各有独立状态，不自动回退或重连。
9. 已停止、运行中、忙碌和活动未知空间的保存与生效符合真实路径；运行观察不足不伪装成功。
10. 快速切换空间、迟到响应和并发保存不会把 A 的状态或写入落到 B。
11. 凭据仍留在所属宿主，授权不可由客户端伪造；无权限模型不能仅靠界面隐藏。
12. 在隔离的官方 Desktop 和 Web 实际走完主要流程并验证键盘操作；源码测试、构建与历史验收不替代实际交互证据。

实施后按 AGENTS.md 运行完整规定检查。本文当前只有方案，不宣称任何运行验收。

## 11. 未决项

- **来源与共享策略的写入耦合。** "保存共享策略是否会退出主空间继承"需要单一、显式的来源提交点，本轮不动数据结构，只把行为目标固定下来。
- **运行观察的覆盖面。** 空间策略版本是否进入实例观察、以及观察不全时如何呈现，尚未定论。
- **导入引用契约的真实形态。** 主空间来源、本地来源与旧目录映射三种结果如何在同一导入流程中表达，尚无冻结契约。
- **官方设置嵌入点。** 能否嵌入官方主空间设置表单，需要交互实测；在确认前只能提供跳转入口。
- **逐连接授权。** 需要新增权限需求才能做，本轮不做。
- **旧共享后端退役。** 需要全部消费者迁移方案，本轮不做。

## 12. 不扩大本轮范围的决定

直接采用主空间默认来源、空间详情的单空间权威、旧目录兼容共存、无自动迁移和导入按需处理，不逐项追加确认。若后续明确要求逐连接授权或退役旧目录，再单独界定范围，不能通过隐藏控件或删兼容入口代替。
