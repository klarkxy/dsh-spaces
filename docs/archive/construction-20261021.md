## 1. 交付目标与范围

用户随后授权将主服务/facade 接入正式插件，并补齐模型发现、默认值、controls 与普通创建后的真实 Agent/UI。本轮按此追加授权实施，记录于 [正式插件集成报告](llm-formal-plugin-agent-ui-results-20261021.md)；真实 Supervisor/CLI 与正式包安装替代前轮启动 fixture，SDK 固定不动。阶段结果与全仓检查、Astra 复核分别记录，不扩写为 S1/P0 或完整 P1 已通过。

先将现有 UI、Desktop、SDK 和 Browser 改动收成可追溯的验收基线，再交付“主空间配置一次模型，新建子空间直接使用”。保留旧 shared/local 模型路径、现有消息总线和看板封存状态。

本轮不实施 Terminal Space、看板唤醒、通用消息产品、`ctx.web` 转发、任意 `ctx.*` 远程代理、真实 Home 迁移或公开发布。通道通用性用测试 handler 证明，不增加第二个产品消费者。

技术设计、wire schema 和兼容规则以 LLM 计划为准；本文件只定义施工顺序、负责人、交付证据与门槛，避免复制另一份协议定义。

## 4. P0 四道技术门

| 门 | 必须证明 | 失败时处理 |
|---|---|---|
| G1 主空间接入 | 官方 Desktop/Web 的已运行主空间插件能取得所需公开服务；私有 loopback listener、可信注册、Home/实例绑定与 dispose 可用；多主空间实例拒绝歧义 | 报告具体缺失接口/身份边界；不读真实 Home，不以 Supervisor 重建配置代替 |
| G2 官方调用一致性 | 官方 adapter/prepareCall 与最终 controls 保持同一目标及能力代次；默认变化只影响后续模型调用；不一致时供应商零调用并返回配置变化错误 | 不用私有字段、复制 resolver 或重新 prepare 掩盖；记录最小官方扩展需求后停止依赖施工 |
| G3 附件和并发隔离 | 两个来源可使用相同 session/attachment ID 而不串数据；请求级读取在原授权范围；主空间 sacred trees 字节不变 | 不通过全局替换 attachment store 或静默丢附件降级；未支持模态明确记录 |
| G4 官方 Agent/UI | 虚拟模型可被发现并完成首次调用、工具后续轮；取消/断流只有一次供应商请求，官方 retry 插件不会使本路径重发；replay 行为有证据 | 不以 waterfall mock 或伪造 endpoint/key 宣称通过；保留最小失败案例 |

原型默认使用本地受控 provider 和标记凭据，避免消耗真实供应商额度。官方 host、Agent、adapter 与传输必须是真实链路；mock 的只有供应商边界。

主空间是用户最初打开并配置模型、加载 Spaces 插件的官方宿主进程，不能改为 `spaces-hub` 管理器。生产中可为 Web 的 `web` profile 或官方 Desktop 的 `desktop` profile，身份必须由可信宿主元数据、loader 根及 Home 绑定证明，不由请求自称。验收保持产品行为不变：Web 使用官方 CLI 支持的专用非 web profile＋官方 web 模板＋预先生效的隔离 patch，Desktop 沿用官方 desktop profile＋独立数据路径；只给这个验收宿主自身配置本地 mock，不读、复制或迁移真实 web 配置。G1/G4 要求这些真实官方进程、实际插件、公开服务与 UI/Agent 证据；注入身份夹具只证明单元边界。验收记录必须写出实际 profile，并明确未运行受保护的 web profile，不能将其写成字面 web 路径实机通过。任何启动会写受保护树则停止该案例，不豁免目录规则。

P0 输出应包含已验证官方包版本和公开导出、契约冻结表、准备句柄/控制参数/附件的精确接线方式以及未决项。若公开 API 不能满足某道门，主代理先给出事实与最小方案修订，不能让后续 worker 基于假设继续施工。修订原方案范围或需要改上游时另行明确决策。

| Worker C：子空间 Agent | llm-bridge adapter、activity 接线及领域测试 | P1 已由主代理落地并冻结的 LLM 共享类型；端到端依赖 A/B | 官方 Agent 集成、显式模型兼容、Apply/replay |
| Worker D：创建/UI | 创建用例、策略投影、模型来源 UI、模板/分享、DOM 测试 | 冻结 policy/API；接线依赖 C | 零配置创建闭环及旧管理入口 |
| 独立验收 | 只读评审已交付产物；必要验证临时文件仅落指定证据目录 | 阶段实现和原始测试结果 | 证据支持的通过/修改/阻塞结论 |

主代理独占 `src/core/domain/llm-connections.ts`（包括 reserved route 与新旧 policy）、`src/adapters/node/llm-policy-store.ts`（schema/CAS）、`src/shared/llm-api.ts`（API）及新增 `src/shared/capability-channel.ts`。C 只消费冻结后的 route/policy，D 只消费冻结后的创建/UI API，不并行修改这些文件。确需转交时先结束原写者任务、核对差异，再书面移交单一所有权。

P0 结束时由主代理冻结 LLM capability v1 契约：`describeDefault/prepare/stream/release` 方法及 payload、句柄身份、错误/domainCode、StreamChunk 与外层帧/终态映射、附件与 controls 边界。契约记录在原技术计划，正式 LLM 共享类型的精确文件路径随 P0 决议登记为主代理独占，P1 由主代理唯一落地；共享类型文件及其检查通过之前不得派发 B/C 正式实现，二者只读消费。契约变化先由主代理修订并同步消费者，禁止 handler 和 adapter 各自定义 wire。

通用层不得导入 llm-bridge、StreamChunk 或 LLM policy；依赖只能从 LLM 模块指向通用层。`packages/llm-bridge/src/settings-provider.ts` 的 route 冲突接线、`src/adapters/node/supervisor/llm.ts` 与 `src/adapters/node/llm-host.ts` 默认由主代理持有；需要 worker 修改时先逐文件串行移交，不能凭 A/C 的目录描述获得写权。

这只是职责分组，不是通配路径写权限。每次派发前列出精确文件；如 A/B/C/D 需要同改一个入口，由主代理指定唯一写者或串行移交。共享 schema、package/lock、构建清单不交给多个 worker 并行修改。所有子任务 prompt 使用英文，并明确禁止提交、推送、发布和受保护目录写入。

每包交付格式固定：修改文件、契约变化、实际运行检查及结果、失败/跳过、遗留项、证据路径。不以 worker 自述“完成”代替父代理集成与独立验收。

## 6. P1—P4 的核心验收案例

1. 新空间无本地 Key、无共享连接即可用主空间默认；创建时主空间没模型也能保存空间定义，调用时显示实际失败。
2. 旧 v1 all/selected/none、无文件旧空间、本地和会话显式选择保持语义；无自动迁移。未知/损坏 policy 和 catalog 明确失败，不能当作空配置。
3. 当前默认在每次模型调用准备时冻结；后续调用能见新默认，在途不混模型；配置变化拒绝发生在供应商请求前。
4. 请求、StreamChunk、工具/reasoning/usage/finish/replay 完整传输；EOF 无 terminal 判失败，部分输出保留，不补成功终态。
5. 来源/token/scope/epoch/generation/target 全部绑定；跨空间句柄、伪造来源、旧实例、浏览器 Cookie/Origin 和未来能力调用均拒绝。
6. caller/target 退出、取消、超时与未知结果语义分开；未结束 handler 不提前释放执行配额；无重发、重连、续流或备用路径。
7. 两空间并发附件和会话隔离；工具仍在子空间执行；供应商标记 Key 不进入子空间、Supervisor 诊断和导出物。
8. busy/unknown Apply 仍拒绝，idle reservation 仍有效；通用活动统计不替代 Agent/maintenance 判断。
9. 普通创建、模板、蓝图和分享使用同一策略规则；显式绑定保留，导入物不能携带 capability 授权或运行实例秘密。
10. 旧消息总线通过回归；看板仍封存；生产 discovery 不包含测试 handler 和未实现未来能力。

所有测试纳入正式清单，不只留在临时原型。数值资源上限在 P0 按真实附件/流需求确定并写进契约，不机械继承旧总线 64 KiB。

### 7.2 历史持续 UI 调查

`read.deadline`、请求发出前停顿、`ECONNRESET`/1006 保留独立问题编号，不能因看板封存关闭。本方案不自动启动历史故障专项；仅当其影响本轮验收或用户另行要求时建立独立任务和验收范围。需要继续调查时，在新隔离环境收集浏览器网络时间、受控 NetLog、服务端耗时及进程/代次关联；日志限本地受控数据并脱敏。先归因再修复，不加自动重连、超时重试或恢复入口。
