# 主空间继承与专用 LLM 委派合同

> 状态：**已归档的历史合同。** LLM 委派与 `@dsh-spaces/llm-bridge` 已退役，现行做法是从主空间一次性同步模型配置，见 [现行架构](../architecture.md) §6。本文只记录委派方案当时的语义。
> 不在本文范围：本地与会话模型选择（见现行架构 §6.2）、历史设置收敛方案（见 [归档记录](model-settings-redesign-20261022.md)，不是现行能力）。
> 故障政策以 [let it crash](../let-it-crash.md) 为唯一权威。
> 2026-10-25 修订：本文此前是一份包含通用能力委派平台的施工计划。**通用能力平台没有实现，也不是现行能力**，已从合同移除；保留的是主空间继承与专用 LLM 委派的公共语义。

## 1. 目标与边界

用户在主空间配置一次模型供应商和 API Key，普通空间不必再导入第二份配置或填写凭据即可调用模型。

- **只服务 LLM 调用。** 委派通道只承载主空间模型的准备、流式调用、取消和附件协作。它不是通用 RPC、不是空间间消息通道、不承载任意 `ctx.*` 调用。
- **主空间是唯一执行位置。** 主空间是同一 Home 中用户配置模型并加载 Spaces 的官方宿主进程（Web 通常是 `web` profile，官方 Desktop 是 `desktop` profile），不是 `spaces-hub`。
- **不复制主空间配置。** Spaces 不读取主空间的有效配置再重建推理，不把主空间 provider 或 Key 写进普通空间，也不在 Supervisor 里重建官方 Agent、会话或存储。
- **不新增恢复语义。** 不重试、不重连、不切换执行器、不迁移在途请求、不代启主空间。

### 1.1 与本地选择的关系

主空间继承与空间本地默认、会话显式选择是不同来源，不能混写为一份"全局配置"。主空间继承由主空间官方服务提供连接与凭据，模型正文经 Supervisor；本地/会话选择由该空间自己的官方 adapter 直连供应商。空间当前使用哪种来源是该空间的策略事实，所有权见现行架构 §4。

## 2. 调用链与数据面

```text
子空间官方 Agent
  → LLM bridge（子空间内）
  → Supervisor 委派通道
  → 主空间官方 LLM 服务
  → 官方 adapter → 供应商
```

- **身份与授权。** Supervisor 把调用绑定到具体子进程实例（空间 ID、运行代次、服务纪元）和具体会话。来源不能由请求体自选，浏览器和普通空间不能自行声明自己是某个来源。
- **主空间注册。** 主空间以自身身份向 Supervisor 注册并证明 Home 与 profile 一致；管理器、被监督的子进程和其他非主空间 profile 不能注册为主空间。
- **正文经过 Supervisor。** Supervisor 中转请求与响应内容，因此它是这条调用的数据面参与者；这一点必须在产品说明中如实呈现，不能宣称"请求不离开子空间"。
- **Key 留在主空间。** 供应商凭据只在主空间的官方凭据服务与 adapter 内解析。Supervisor 和普通空间都不取得、缓存或记录 Key。
- **主空间 listener。** 主空间侧使用一个由插件自己持有、生命周期跟随插件的私有回环监听器，不依赖宿主的 Web 服务，不对外暴露任意 HTTP 代理。
- **管理界面与执行位置分离。** 管理界面或管理 profile 退出不会改变主空间继承的执行位置；该路径仍依赖 Supervisor 与主空间。本地/会话选择在同一空间内独立执行。

## 3. 默认模型与来源解析

无显式模型选择的新空间使用虚拟路由，表示"跟随主空间默认"：

```text
provider = spaces-main
model    = default
```

- **"当前默认"是调用准备时的值。** 每次模型调用准备时向主空间读取当前默认；后续调用看到后来保存的新默认。
- **在途调用不改目标。** 已准备并冻结的调用保持原目标；同一 Agent turn 的后续模型步骤可以跟随新的默认。
- **显式配置优先。** 会话显式选择和空间本地默认保持各自语义与原失败。显式目标失效即失败，不转走继承路径。
- **固定主空间模型不等于关闭继承。** 固定主空间的某个可用模型仍是继承路径的一种选择，不要求另外建立连接库。
- **只使用已发现且获授权的目标。** 固定主空间模型来自当前可用目录，不允许客户端提交任意 provider 字符串、端点或凭据。

## 4. 配置冻结与请求一致性

主空间官方调用准备会冻结完整控制项（模型目标、控制参数、能力）。

- 委托在准备阶段绑定真实目标、能力代次和来源实例，返回一次性调用句柄；句柄只在内存中，不持久化、不跨重启重放。
- 发出供应商请求前必须确认冻结目标未发生不可安全对齐的变化；无法保持一致时返回配置变化错误，本次不发出供应商请求，也不自动重新准备。
- 已进入官方准备调用的请求沿用冻结配置，不中途换端点、换 Key 或换模型。
- 控制参数（推理等级、温度、最大输出、停止序列等）在冻结前确定；显式选择与默认值的来源必须可分辨，"当前默认"变更不能悄悄改写已显式选定的推理等级。

## 5. 流、取消与失败

- **完整转发。** 传输官方流式结果，包括文本与工具块、推理块、用量、终止原因和不透明的 replay 状态。不修改被冻结的原请求；需要投影时创建独立的线上投影。
- **部分输出保留。** 断流保留已产生的部分输出，不补造成功。
- **零自动重试。** 继承路径明确声明不重试，不能以"未定义"继承官方默认重试策略。上游存在重试插件时，本路径仍只发起一次供应商调用。
- **取消。** 取消是委派通道的公共方法。消费方返回、取消、来源退出或主空间退出都要释放本次流与句柄。
- **超时不等于未执行。** 超时或连接断开不证明操作没有运行，也不撤销其副作用；没有自动重试或补偿。
- **失败分类。** 默认缺失、目标不兼容、配置变化、附件不可访问、主空间或 Supervisor 不可用、来源未授权等有独立错误类别并脱敏。供应商错误保留可辨识类别，不回传 Key、认证头或请求正文。
- **不自动兜底。** 继承失败不自动回落到本地选择或其他来源。

## 6. 附件、工具、会话与 replay

- **执行位置。** 工具在子空间执行；会话由子空间持久化；主空间只执行模型调用。主空间不创建、不读取子空间会话，也不往自己的 sessions / storages 写子空间数据。
- **附件请求级授权。** 子空间按本次调用的授权范围解析引用，用受限数据与不透明标识交给主空间；主空间按请求隔离读取能力，不替换全局附件服务造成并发串用，不允许任意主机路径读取。
- **不支持的模态明确拒绝**，不静默丢图。文件内容必须先被投影，再作为可解释的内容进入调用。
- **来源隔离。** 会话标识、附件标识与调用句柄都绑定来源实例；同名新实例不是旧实例。
- **replay 保真。** 持久化与重放保留官方可解释的真实 provider/model 信息与原生响应状态，重新打开会话时能分辨"这条历史来自主空间"。本地历史中同名 provider 不能证明主空间来源。

## 7. 授权、可见性与资源限制

- **默认拒绝。** 目标空间必须对来源空间显式授权；未授权、未知来源或非当前实例一律拒绝，不因"能被发现"而获得许可。发现不授予权限。
- **来源由 Supervisor 绑定。** 请求正文不能选择来源；替换进程以相同空间 ID 出现时是新的会话身份，旧会话的未完成工作失败，迟到回复不能用于新调用。
- **注册由 Supervisor 校验。** 主空间注册要核对 Home、profile 身份与当前 Home 写权；管理器、普通子进程和其他 profile 不能注册为主空间。
- **授权矩阵不能只靠自述。** 谁能使用主空间模型必须由 Supervisor 根据受管策略确认，不能只接受主空间注册时声明的权限；该边界未闭合时不得宣称逐空间授权已完成。
- **有界资源。** 并发调用、单请求体、句柄数量、句柄有效期和连接读取都有上限；超出返回明确的过载或超时错误，不无限排队。
- **背压。** 流式转发遵守消费端写背压，不为慢消费者无限缓存。
- **活动记账。** 委派的活动状态与空间生命周期准入分离：它不替代、也不污染空间重启前的忙碌或未知判断。

## 8. 生命周期依赖

| 状态 | 结果 |
|---|---|
| 子空间、Supervisor、主空间都可用 | 继承可用 |
| 主空间退出或未注册 | 该路径失败；Supervisor 不改读配置继续代跑、不自动启动主空间 |
| Supervisor 退出 | 该路径失败；已运行空间保持自身状态，不出现第二个写控制者 |
| 子空间退出 | 释放其句柄与会话授权，迟到回复作废 |

这是一条以主空间存活为前提的可用性契约：关闭窗口是否停止主空间服务由宿主生命周期决定，不由界面显示状态推断。

## 9. 不改变的事实

- 旧空间不被自动改写；新空间明确记录自己的来源策略。
- 模型默认更新影响后续调用，不需要对子空间执行"应用"；空间来源策略变更仍走正常显式管理操作。
- 空间消息总线是独立通道，本委派不取代它；两者解决不同的传输问题。
- 通用能力平台、持久消息、广播、跨机器传输和任意 `ctx.*` 远程调用不是现行能力，也不因本合同而承诺。
