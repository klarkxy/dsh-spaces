# DSH Spaces 0.5.0

Release candidate notes. This version has not been published.

DSH Spaces now runs as a plugin inside compatible DSH Web and Desktop hosts. The host keeps its original application and adds a space rail; a single Supervisor manages independent space processes, plugins, settings and jobs.

- Create Web spaces with an exact official DSH version. Follow the main host's model by default, or configure models in that space. Legacy shared-connection settings are collapsed separately.
- Open, start, stop and restart managed spaces from the Desktop rail. Background service failures preserve the main application and show the actual failure.
- Keep plugin management, ordinary templates and `.dshspace` sharing. Browser Space and Spaces blueprint entry points are not available in this release; their implementations remain in the repository.
- Preserve authentication, per-space data paths, single-writer control and atomic writes. Failed jobs are not replayed; no automatic retry, restart, rollback or recovery is added.

## Installation and compatibility

Install the prebuilt `dsh-spaces-plugin-0.5.0.tgz` into a compatible DSH host using its normal plugin installer. Node 24.21+ within 24.x and Node 26.x are supported; the tested official DSH version is 0.2.1-rc.2. Managed Web spaces support exact DSH versions from 0.2.0-rc.2 onward, subject to their plugin requirements.

0.4.0 was distributed as a standalone desktop application. 0.5.0 supplies a host plugin and does not produce standalone installers or an in-place update for that older application. No old-space migration is performed by this release preparation. Install into an existing DSH host and create spaces there. The workbench remains on protocol 2; components must come from the same verified build.

For an existing host-plugin installation, update the host plugin, stop the Spaces service normally, then reopen Spaces. Current `@dsh-spaces/*` packages are not published to npm; the root repository is not the installable package.

Local verification and its limits are recorded in [the release preparation report](../../tasks/release-0.5.0.md). Prior Desktop, Linux or macOS evidence does not establish current installed-runtime acceptance.
