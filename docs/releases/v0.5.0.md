# DSH Spaces 0.5.0

公共插件目录现由 Spaces 仓库维护，接受独立作者的 npm 插件，支持目录浏览及按包名安装。核心包保持 `dsh-spaces`；npm 发行改为由 GitHub Release 自动触发检查、打包和发布，同时保留 Git 根地址安装。参见[插件贡献](../../catalog/README.md)和[Git 安装](../plugin-standard-install.md#git-source-install)。0.5.0 仍为未发布候选版。

Release candidate notes. This version has not been published.

DSH Spaces now runs as a plugin inside compatible DSH Web and Desktop hosts. The host keeps its original application and adds a space rail; a single Supervisor manages independent space processes, plugins, settings and jobs.

- Create Web spaces with an exact official DSH version. Copy the main space's model configuration once at creation by default (`models-sync`), or configure models in that space; spaces can also preview and sync main-space models on demand (`models.sync`); a running target stays running and uses the verified new configuration on its next model request, while stopped and crashed targets use direct file writes. Each space calls its providers directly with its own configuration.
- The main space's `cordis` preset provides the Creator four-tool set and the space-control tools for lifecycle, plugins, runtimes, model sync and bounded UI automation. Plans bind service epoch, state revision, target fingerprint and expiry; mutations require explicit approval and stop at the first failure without retry or rollback.
- Open, start, stop, restart and jump to space settings for managed spaces from the Desktop rail, with a breathing attention halo when a space has a pending tool approval or question card. Background service failures preserve the main application and show the actual failure.
- Keep plugin management, ordinary templates and `.dshspace` sharing. Browser Space and Spaces blueprint entry points are not available in this release; their implementations remain in the repository.
- Preserve authentication, per-space data paths, single-writer control and atomic writes. Failed jobs are not replayed; no automatic retry, restart, rollback or recovery is added.

## Installation and compatibility

Install `github:klarkxy/dsh-spaces` directly through the compatible DSH host's plugin installer, approving this project's build script when requested. The prebuilt `dsh-spaces-0.5.0.tgz` is an alternative. Node 24.21+ within 24.x and Node 26.x are supported. The build SDK and default runtime for new spaces are `0.2.2-rc.1`; `0.2.0-rc.2` is the minimum supported space runtime.

0.4.0 was distributed as a standalone desktop application. 0.5.0 supplies a host plugin and does not produce standalone installers or an in-place update for that older application. No old-space migration is performed by this release preparation. Install into an existing DSH host and create spaces there. The workbench remains on protocol 2; components must come from the same verified build.

For an existing host-plugin installation, update the host plugin, stop the Spaces service normally, then reopen Spaces. Published versions install as the prebuilt npm package `dsh-spaces`; direct Git-root installation remains supported.

Local verification and its limits are recorded in [the release preparation report](../../tasks/archive/release-0.5.0.md).

## Known limitations

- Browser Space and Spaces blueprint workflows are sealed; their creation, preview, apply, share-code import/export and native Browser presentation are not enabled in this release.
- There is no in-place upgrade or migration from the 0.4.0 standalone desktop application, and no standalone installer is produced.
- npm publication follows the GitHub Release workflow; Git-root and local archive installation remain supported.
- Windows is the locally verified platform. macOS and Linux are not certified for this release; remote HTTPS and arbitrary third-party native hosts remain unsupported.
- Each ordinary space pins an exact DSH runtime. Existing ordinary-space bridges are not automatically realigned to a new component group; an installed bridge does not prove version alignment.
- There is no automatic retry, restart, rollback, restore, repair or interrupted-job replay. Only the bounded Desktop service start/restart exception defined in [let-it-crash.md](../let-it-crash.md) is allowed.
- Unregistered manual DSH processes are outside discovery and shutdown. Backups guarantee only the consistency scope of known, stopped managed spaces, not every possible external writer.
- Space isolation is not a malicious-plugin sandbox, multi-tenant boundary or cross-machine high-availability mechanism.
- Real-Desktop end-to-end acceptance remains incomplete for `plugin.live.*` operations and the `spaces_ui_*` approval flows.

## 中文

本版改为安装在兼容 DSH Web / Desktop 内的 Spaces 插件。原应用保留，空间栏承载普通空间，一个 Supervisor 负责管理；不再提供独立桌面安装程序。

新建空间使用 Web，可选择官方 DSH 精确版本，默认在创建时从主空间一次性复制模型配置（`models-sync`），也可在空间内自行配置；空间还可在“常规”页查看已保存的模型状态并按需再次同步主空间配置（`models.sync`），运行中空间通过自身设置接口写入并读回校验，保持运行，下一次模型请求使用新配置；已停止或异常退出的空间直接写配置文件，各空间均使用自身配置直接调用模型。主空间的 `cordis` preset 提供 Creator 四工具及空间总控工具，覆盖生命周期、插件、运行时、模型配置同步和有界界面自动化；计划绑定服务纪元、状态版本、目标指纹和有效期，变更需显式审批，首处失败即停止，不重试、不回滚。Desktop 空间栏提供打开、启动、停止、重启和打开空间设置，并在空间存在待审批工具调用或提问卡片时展示呼吸提示光环；后台错误保留主应用。插件管理、普通模板及 `.dshspace` 分享保留，Browser Space 与 Spaces 蓝图入口本版不开放。

可直接安装 Git 根地址 `github:klarkxy/dsh-spaces`，或使用预构建的 `dsh-spaces-0.5.0.tgz`。构建 SDK 和新空间默认运行时为 `0.2.2-rc.1`，普通空间最低运行时为 `0.2.0-rc.2`。本版没有从 0.4.0 独立桌面应用原地升级或迁移旧空间的流程；已有宿主插件按正常插件更新、停止 Spaces 服务、重新打开的顺序升级。

## 已知限制

- Browser Space 与 Spaces 内蓝图工作流封存；创建、预览、应用、分享码导入导出及原生 Browser 展示本版不开放。
- 没有 0.4.0 独立桌面应用的原地升级或旧空间迁移，也不产出独立桌面安装程序。
- npm 发布跟随 GitHub Release 工作流；同时支持 Git 根地址或预构建归档安装。
- 本版只在 Windows 完成本地验收；macOS、Linux、远程 HTTPS 和任意第三方原生宿主未认证。
- 每个普通空间固定精确 DSH 运行时；既有空间桥接不会自动按新组件组重新对齐，已安装不等于版本一致。
- 不提供自动重试、重启、回滚、恢复、修复或中断任务续跑；唯一例外是 [let-it-crash.md](../let-it-crash.md) 定义的 Desktop 手动服务启动/重启。
- 未登记的手工 DSH 进程不属于可发现、可停机范围；备份只保证已知受管空间停止后的一致性范围，不保证所有潜在外部写者都已停止。
- 空间隔离不是恶意插件沙箱、多租户隔离或跨机器高可用。
- 真实 Desktop 的 `plugin.live.*` 操作和 `spaces_ui_*` 审批流程端到端验收仍不完整。
