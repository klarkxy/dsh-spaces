# DSH Spaces 0.5.0

Release candidate notes. This version has not been published.

DSH Spaces now runs as a plugin inside compatible DSH Web and Desktop hosts. The host keeps its original application and adds a space rail; a single Supervisor manages independent space processes, plugins, settings and jobs.

- Create Web spaces with an exact official DSH version. Follow the main host's model by default, or configure models in that space.
- The main space's `cordis` preset provides the Creator four-tool set and the space-control tools for lifecycle, plugins, runtimes, model policy and bounded UI automation. Plans bind service epoch, state revision, target fingerprint and expiry; mutations require explicit approval and stop at the first failure without retry or rollback.
- Open, start, stop and restart managed spaces from the Desktop rail. Background service failures preserve the main application and show the actual failure.
- Keep plugin management, ordinary templates and `.dshspace` sharing. Browser Space and Spaces blueprint entry points are not available in this release; their implementations remain in the repository.
- Preserve authentication, per-space data paths, single-writer control and atomic writes. Failed jobs are not replayed; no automatic retry, restart, rollback or recovery is added.

## Installation and compatibility

Install the prebuilt `dsh-spaces-plugin-0.5.0.tgz` into a compatible DSH host using its normal plugin installer. Node 24.21+ within 24.x and Node 26.x are supported. The build SDK and default runtime for new spaces are `0.2.2-rc.1`; `0.2.0-rc.2` is the minimum supported space runtime.

0.4.0 was distributed as a standalone desktop application. 0.5.0 supplies a host plugin and does not produce standalone installers or an in-place update for that older application. No old-space migration is performed by this release preparation. Install into an existing DSH host and create spaces there. The workbench remains on protocol 2; components must come from the same verified build.

For an existing host-plugin installation, update the host plugin, stop the Spaces service normally, then reopen Spaces. Current `@dsh-spaces/*` packages are not published to npm; the root repository is not the installable package.

Local verification and its limits are recorded in [the release preparation report](../../tasks/archive/release-0.5.0.md). Prior Desktop, Linux or macOS evidence does not establish current installed-runtime acceptance.

## 中文

本版改为安装在兼容 DSH Web / Desktop 内的 Spaces 插件。原应用保留，空间栏承载普通空间，一个 Supervisor 负责管理；不再提供独立桌面安装程序。

新建空间使用 Web，可选择官方 DSH 精确版本，默认跟随主空间模型，也可在此空间配置。主空间的 `cordis` preset 提供 Creator 四工具及空间总控工具，覆盖生命周期、插件、运行时、模型策略和有界界面自动化；计划绑定服务纪元、状态版本、目标指纹和有效期，变更需显式审批，首处失败即停止，不重试、不回滚。Desktop 空间栏提供打开、启动、停止和重启；后台错误保留主应用。插件管理、普通模板及 `.dshspace` 分享保留，Browser Space 与 Spaces 蓝图入口本版不开放。

安装文件为 `dsh-spaces-plugin-0.5.0.tgz`。构建 SDK 和新空间默认运行时为 `0.2.2-rc.1`，普通空间最低运行时为 `0.2.0-rc.2`。本版没有从 0.4.0 独立桌面应用原地升级或迁移旧空间的流程；已有宿主插件按正常插件更新、停止 Spaces 服务、重新打开的顺序升级。

## 已知限制

- Browser Space 与 Spaces 内蓝图工作流封存；创建、预览、应用、分享码导入导出及原生 Browser 展示本版不开放。
- 没有 0.4.0 独立桌面应用的原地升级或旧空间迁移，也不产出独立桌面安装程序。
- `@dsh-spaces/*` 尚未发布到 npm；只使用本地预构建 tarball 安装。
- 本版只在 Windows 完成本地验收；macOS、Linux、远程 HTTPS 和任意第三方原生宿主未认证。
- 每个普通空间固定精确 DSH 运行时；既有空间桥接不会自动按新组件组重新对齐，已安装不等于版本一致。
- 不提供自动重试、重启、回滚、恢复、修复或中断任务续跑；唯一例外是 [let-it-crash.md](../let-it-crash.md) 定义的 Desktop 手动服务启动/重启。
- 未登记的手工 DSH 进程不属于可发现、可停机范围；备份只保证已知受管空间停止后的一致性范围，不保证所有潜在外部写者都已停止。
- 空间隔离不是恶意插件沙箱、多租户隔离或跨机器高可用。
- 真实 Desktop 的 `plugin.live.*` 操作和 `spaces_ui_*` 审批流程端到端验收仍不完整。
