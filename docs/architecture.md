# DSH Spaces 现行架构

> 状态：2026-10-25 现行架构基线。本文描述当前产品边界、数据所有权和运行语义，不是某次实施或验收记录。故障政策以 [let it crash](let-it-crash.md) 为唯一权威；安装与操作见 [工作台](workbench.md) 和 [标准安装](plugin-standard-install.md)。

## 1. 产品边界

DSH Spaces 是安装进兼容 DSH Web 或 Desktop 的多空间插件，没有独立客户端，也不修改官方 SDK。插件 tarball 是 Spaces 的唯一发行单元；蓝图协议包可以独立安装和使用的边界见 [BLUEPRINT](blueprint.md)。

产品面向单机、单用户和同一 OS 用户信任域。空间隔离用于分离插件组合、会话、工作数据和管理权限，不构成恶意插件沙箱、多租户隔离或跨机器高可用。

普通空间先确定 base 及其产品版本，再组合扩展插件。当前只开放 Web base，对应官方 DSH Web 发行版。Browser base 的独立产品版本、框架依赖及扩展实现保留，但创建、启动和原生展示入口封存，不属于本次发行开放能力。模板和分享保留 base 身份，不进行旧空间迁移。

## 2. 角色与职责

| 角色 | 职责 | 明确不负责 |
| --- | --- | --- |
| 主应用宿主 | 展示原应用、承载 Spaces 入口；主空间可提供自己的官方 LLM 服务 | 不因此获得普通空间的管理写权 |
| Supervisor | 每个 Home 一个；持有 Spaces 管理写权、监督子进程、执行任务、提供稳定管理入口和受权路由 | 不收养外部进程，不自动恢复失败环境 |
| 管理空间 `spaces-hub` | 承载管理工作台和受认证的管理转接 | 不是主空间，不复制一套后台 |
| 普通空间 | 独立 DSH 进程、插件组合、会话和工作数据 | 不暴露管理 Remote，不启动第二个 Supervisor |
| view bridge | 视图握手和受权的空间间消息能力 | 不承担管理或模型配置职责 |
| LLM bridge | 主空间继承和本地模型的接入 | 不创建第二套会话、Agent 或管理器 |
| Creator channel | 身份确认主空间经受权工具发起一次空间创建 | 不开放任意管理命令、任意现有空间目标或模型数据面 |
| Browser bridge | Browser Space 的界面与受权浏览器能力 | 不提供任意网页读取、脚本执行或管理通道 |

主应用、`spaces-hub` 和普通注册空间是不同角色。普通空间成员资格只认 Spaces 注册项；不能仅凭目录存在或名称相似把其他 profile 当作普通空间。

### 2.1 Creator 空间创建

主空间（web/desktop profile）在 Creator（`cordis` preset）下获得四个宿主工具：`spaces_context`、`spaces_create_preview`、`spaces_create_execute`、`spaces_job`。它们只通过 Supervisor 的独立 Creator scope 调用，不走管理 Remote，也不依赖 LLM 服务；scope 只对 `context`/`createPreview`/`createExecute`/`job` 有效，不进会话、日志或端点记录。

创建语义是单个不可取消的组合作业：prepare（含运行时安装）→ create → view-bridge → llm-policy（选 `main` 模型源时）→ 逐项插件安装并读回校验 → 可选 start。预览把输入冻结成一次性计划，绑定服务纪元、状态版本和过期时间；执行在独立 `approveEscalation` 闸门后按 requestId 串行。首个失败即停止：已完成步骤保留为真实结果，未运行步骤保持 `not-run`，不重试、不回滚、不续跑。插件来源只允许 npm 精确版本或 GitHub 完整 commit（可带安全子目录），install script 只在审批明确列出的 `allowBuilds` 键下运行。

## 3. 控制面与展示面

### 3.1 管理读取与写入

管理工作台经认证 Host 转接访问 Supervisor。普通空间和其他宿主不能因展示空间栏而调用管理写入。

普通写入携带服务纪元、预期状态版本和请求 ID。比较发生在实际串行执行边界；相同请求 ID 只能对应同一命令，刷新只读取原任务。危险操作先预览，执行时再次检查服务纪元、状态版本、目标指纹和计划有效期。

管理状态区分协议版本、服务纪元、状态版本和可用性。空间运行状态、任务结果和服务可用性是不同事实。读取接口可以返回瞬时投影；状态版本不表示任务列表、日志和所有磁盘读取都来自同一一致性快照。

### 3.2 视图展示

展示链为：

```text
外层宿主 → Supervisor 受限展示页 → contained manager → 普通空间视图
```

Supervisor 签发有期限、单次使用并绑定父来源和通道的入口票据。浏览器不取得 Node 管理 bearer。各层校验窗口来源、精确 origin 和通道；空间视图还校验服务纪元、空间 ID 和运行代次。

官方 Desktop 空间栏点击即打开：先核实当前状态，已运行时直接进入，已停止时发起一次正常启动，正在启动时只等待已有操作。侧栏显示运行状态，右键提供启动、关闭和重启。这个入口仅限身份已验证的 Desktop 宿主和受管子空间，写入仍由 Supervisor 校验服务纪元、状态版本、计划与单写者权限。通用嵌入空间栏仍只选择已运行视图；展示权限不授予管理权。关闭标签不会停止空间或 Supervisor。由官方 Desktop 启动的 Supervisor 跟随该 Desktop 退出：Desktop 宿主进程结束时，Supervisor 执行一次正常关闭（停止它管理的空间、释放运行权后退出）；关闭失败时保持原样并保留运行权，不强杀、不重试。由 Web 启动的 Supervisor 不受影响；Desktop 附着到已有 Supervisor 时不改变它的生命周期。

### 3.3 Desktop 管理服务的一次启动

官方 Desktop 打开应用时，宿主按当前 Home 发起或加入一次后台管理服务启动，并保存该次终态。界面刷新只重新加入这份记录，不构成另一次启动。失败和正常停止都不自动重启，也不自动启动子空间。同一宿主进程内，停止后的服务保持停止。正常再次打开应用是一份新启动；已有的确认式手动服务操作也建立一份新操作。

设置与新建只记录最后一次导航意图，回到主空间取消这次跳转，不取消后台启动。原始失败、随后的停止结果和进程记录是否保留分开显示，并去掉路径、命令和秘密。健康的旧服务可以连接。未提供启动观察的宿主是明确兼容失败，不改走自动恢复，也不能据此断定服务没有启动。普通 Web 仍是用户点击的一次初始化。

## 4. 数据所有权

| 数据 | 权威所有者 | 写入边界 |
| --- | --- | --- |
| 普通空间成员资格、显示元数据和运行时 pin | Spaces 注册信息 | Supervisor 管理写入 |
| 普通空间插件组合 | 对应空间 profile | 受控安装与维护操作 |
| 普通空间会话、工作数据、本地设置和本地凭据 | 对应空间数据根 | 该空间及授权管理操作 |
| 主应用会话、设置和凭据 | 主应用原有位置 | 主应用；Spaces 不迁移或复制 |
| 主空间连接、默认模型和凭据 | 主空间官方服务 | 主空间官方设置与调用准备 |
| 任务、计划和故障证据 | Spaces 控制数据 | 单写者、原子发布和真实失败记录 |
| 组件制品与选择 | Home 外的受控工具区域 | 同组制品校验与正常启动/维护 |

Spaces 不扫描并收养其他 profile。直接创建、普通模板和 `.dshspace` 分享导入可以复用创建语义，但格式解析、空间定义发布、插件安装、配置写入和空间启动仍是不同阶段。Spaces 内蓝图创建工作流当前封存，不参与这些入口。

## 5. 身份、并发与失败

- Home 运行权、管理事务互斥和冷启动串行化是不同边界。
- 公开服务纪元不等于释放运行权所需的秘密。
- 空间实例由服务纪元、空间 ID 和运行代次共同识别；同名新进程不是旧实例。
- 只有新的用户启动才能在互斥保护下退休本次启动最初观察到、且可证明已死亡的允许类型租约。
- 只读发现不清锁、不退休记录、不触发启动或写入。
- 提交前失败不发布新结果；提交后失败保留真实现场和部分改变。
- 中断任务不重放。超时或响应丢失不证明副作用没有发生。
- 单个空间失败不连带停止健康空间；管理进程致命失败按自身边界退出。

完整政策和唯一手动服务启动/重启例外见 [let it crash](let-it-crash.md)。

## 6. LLM 数据面

当前存在两种模型来源，不应混写为一份“全局配置”。

### 6.1 主空间继承

新 Web 空间默认可以跟随主空间模型；Browser 不加载此模型链。调用链为：

```text
子空间 Agent → LLM bridge → Supervisor → 主空间官方 LLM 服务 → 供应商
```

主空间拥有连接、官方 adapter、调用准备和供应商凭据。子空间拥有自己的 Agent、工具、会话和附件授权；Supervisor 不复制主空间配置或凭据，但会中转请求和响应内容，因此属于该调用的数据面。

主空间继承依赖子空间、Supervisor 和主空间同时可用。主空间或 Supervisor 退出后，该路径失败；不自动启动主空间、改读配置、切换供应商或迁移在途请求。

### 6.2 本地与会话选择

空间本地连接、本地默认和会话显式选择保持原有优先与失败语义。显式目标失效时失败，不自动改走主空间。

模型来源切换是独立决定，不应被其他设置保存暗中改变。当前设置界面和导入映射的剩余收敛工作见 [模型设置重订方案](plans/model-settings-redesign-20261022.md)；该方案未完成的条目不是现行能力声明。

## 7. 通信通道

| 通道 | 用途 | 语义 |
| --- | --- | --- |
| 管理 RPC | 状态、任务、计划、产品和 LLM 管理 | 认证、封闭方法、管理 Origin、epoch/revision |
| 视图门户 | 宿主、manager 与空间视图展示 | 单次入口、精确来源、展示与管理分权 |
| 空间消息总线 | 普通空间之间的单结果请求/响应 | 私有 IPC、目标白名单、有界内存、无重放 |
| LLM 委派 | 主空间模型准备、流式调用、取消与附件协作 | 专用受权通道、单次派发、背压与资源限制 |
| Creator channel | 主空间创建空间的 scope 调用与身份挑战 | loopback-only、无 Cookie/Origin、单注册、一次性计划 |

旧消息总线和 LLM 委派解决不同传输问题，可以共存。通用能力平台、持久消息、广播、跨机器传输和任意 `ctx.*` 远程调用不是现行能力。

## 8. 制品、版本与升级

Spaces 以同一构建的不可变组件组发行 Supervisor、管理插件、view bridge、Browser、LLM bridge 和安装 worker。制品按版本与摘要校验，不混用不同构建。

当前目标宿主为 `@deepseek-ai/dsh` **0.2.2-rc.1**（Cordis 4.1.0、loader 1.1.0、schemastery 3.19）。宿主自身要求 Node ≥24.9；本项目 engines 为 Node 24.21+ 的 24.x 或 26.x。宿主插件声明的 peer 范围接受 0.2.0-rc.2 / 0.2.1-rc.2 / 0.2.2-rc.1；官方升级指南只记录到 v0.2.2-alpha.3，rc.1 差异（Cordis `internal/config` 首参由 config 改为 fiber、`agent/request` 标记 deprecated、`GenerateOptions.purpose` 改为生产方声明合并、fs-observation-policy 默认禁用并新增 `apply_patch`）以版本锁定源码为补充依据。这些语义差异不改变本产品的授权、隔离和失败政策。

`@klarkxy/dsh-dev-index` 作为 canonical 行随宿主插件和 view bridge 的组合 patch 预装：主空间与每个 Web 子空间都获得该工具插件，Browser base 在其 profile patch 中显式禁用同一行 id。

升级 Spaces 的正常路径是：

1. 用户通过官方插件管理更新宿主中的 Spaces 插件。
2. 用户在管理工作台停止 Spaces 服务。
3. 用户重新打开 Spaces，新的 Supervisor 选择宿主插件携带的组件组。

管理插件在管理器启动前对齐。普通空间获得随组桥接；既有空间桥接是否已按当前组重新对齐必须据实展示，不能把“已安装”直接写成“版本已一致”。空间 DSH 运行时 pin 与 Spaces 组件组版本是两个坐标：管理空间跟随宿主，普通空间固定精确 DSH 版本并按用户操作切换。

应用内自我更新、一次性启动器交接和旧恢复命令不是现行能力。

## 9. 快照与外部进程

备份支持创建、查看和删除，不支持产品内恢复。创建备份会停止受管空间，但 Supervisor 无法发现从未登记的手工 DSH 进程，因此快照的一致性范围只能是“已停止已知受管空间后的副本”，不能宣称所有潜在外部写者均已停止。

不通过扫描端口、猜测 Home、收养进程或强制终止来补齐这个边界。需要更强保证时，必须依赖可证明的上游实例登记或写租约能力。

## 10. 扩展边界

蓝图描述插件组合或配置配方，不是备份、签名、兼容认证或执行脚本。独立 Creator 的当前 profile 归并与 Spaces 的新空间创建是不同执行语义，不能因共享格式而承诺得到相同结果。

**Spaces 内蓝图工作流当前封存。** 蓝图创建、生成、预览、应用和分享码导入导出暂停，公共请求返回 `workbench/unsupported`；普通模板与 `.dshspace` 分享归档继续可用。独立蓝图包、协议和既有文件保留，待 Spaces 核心系统稳定后再评估唤醒。

新能力必须明确目标、来源身份、方法、权限、资源限制、取消和失败语义。发现不授予权限；管理能力不能借普通视图或 LLM 通道绕过 Home 写权。未实现的通用能力不应出现在现行架构或产品 discovery 中。
