# 核心思想：let it crash

插件由用户自由选择和组合。插件错误、依赖冲突、配置不兼容、启动失败和进程崩溃，都是允许出现的结果。DSH Spaces 不承诺任意插件组合都能正常运行，也不负责把失败的环境修复成可运行状态。

出错时，让失败的操作、插件或进程按照其原有执行边界失败或退出。Spaces 负责如实记录失败，并在仍可用的界面或本地输出中说明发生了什么、已知原因是什么。无法确定根因或具体插件时，明确说明未知，不猜测。

不提供故障后的自动或手动恢复流程：不重试失败操作、不自动重启或重新连接失败组件、不回滚、不恢复快照、不重装依赖、不自动修改配置或禁用插件、不切换版本或实现、不进入安全模式或救援模式、不续跑中断任务。

正常的用户主动启动、停止、重启、安装、卸载和配置操作，仍然是独立操作。它们不构成恢复承诺，不由错误处理器代替用户发起，也不包装成“检查并修复”“恢复中断任务”等入口。

安全边界、数据隔离、输入和路径校验、单写者约束、原子文件写入及必要的资源释放继续有效。校验失败就拒绝并说明原因，不自动纠正。允许崩溃不等于允许越权、泄露凭据、伪造成功或扩大故障影响。

本文件是当前唯一有效的故障政策。其他文档引用它，不再各写一套恢复解释。

**运行时已符合 let it crash（产品路径）。** 公开恢复命令失败且不转发到旧实现；中断任务失败留证、不重放；Doctor 只诊断。源码里仍可能留着未接线的历史恢复模块（例如 `packages/doctor/src/recover.ts`、`RestoreSession`、底层 `SnapshotStore.restore`），那不是产品入口。未在本机用官方 DSH CLI / 浏览器跑完的矩阵项见 [tasks/q-coverage.md](../tasks/q-coverage.md)。启动若仍走运行时安装 IO，继续需要 `--snapshot-worker`。

## 两个必须明确的解释

**不是“只取消自动恢复，手动恢复仍然保留”。** 不需要帮助用户恢复。一键修复、恢复向导、Doctor 恢复命令、失败任务续跑，也不能换个名字留下。

**不是“一个插件报错，就主动杀掉整个应用”。** 操作失败就让操作失败；空间进程崩溃就记录空间崩溃；管理进程发生致命错误就报告后退出。既不抢救，也不人为扩大故障。一个插件记录错误但宿主仍正常运行时，不人为杀掉整个进程；一个空间退出时，不连带关闭其他健康空间。

## 错误提示

已知原因时：

```text
空间 coding 启动失败

阶段：加载插件
插件：example-plugin@1.2.3
原因：缺少服务 example.database
退出码：1

该次启动已失败。

查看错误详情    复制脱敏日志
```

不知道根因时：

```text
空间 coding 的进程已退出

观察到：进程收到 SIGKILL
根因：无法从现有输出确定
插件归属：未能归属到单个插件
```

不出现：已自动修复、正在恢复、建议重新安装、检查并恢复、回滚后重试。

“说明错误”不等于“提供修复步骤”。原始错误也不能未经处理就暴露 token、Cookie、凭据或聊天内容。无法确定插件归属时，写“未能归属到单个插件”，不能把最近安装的插件直接认定为原因。

错误页只留下错误详情、查看日志、复制脱敏日志。常规启动、停止、卸载等操作保留在正常管理位置，不包装成“一键恢复”。

## 必要边界

| 事项 | 目标处理 | 禁止的变体 |
|---|---|---|
| 异常捕获 | 在必要边界补充上下文、脱敏、报告，再抛出或返回真实失败；致命顶层异常报告后退出 | catch 后返回空配置、默认成功或继续执行依赖步骤 |
| 提交前失败 | 未切换到新结果，保留原指针；这不是回滚 | 把“没有提交”写成恢复能力 |
| 提交后失败 | 保留真实失败现场与可能的部分改变 | 再把旧环境写回去 |
| 浏览器刷新 | 读取同一个仍在执行的任务，不重发变更 | 后端已中断时自动重放；轮询触发接管或重启 |
| 进程中断后重开 | 展示中断失败或结果无法确认；保留最后阶段和证据 | 重放命令、对账修补环境、把“没有记录完成”当成“命令没有生效” |
| 导入 | 分开「空间定义」「插件安装」「空间启动」；合法但不兼容的组合可以存在并在启动时失败 | 要求所有插件启动成功才允许空间存在；为了验收变绿而换依赖、禁用插件 |
| 导入失败清理 | 只清理本次能证明归属、尚未发布的临时资源 | 回滚已发布空间、删除原有空间、跨重启清理与恢复服务 |
| 批量 | A 成功保留、B 失败、C 未执行；整批失败终止 | 失败项重试、剩余项继续、中断续接；把旧失败改成成功 |
| 原子写入 | 未提交的临时文件不替换原文件 | 已提交失败后再写回旧文件 |
| `finally` 清理 | 有界释放本次持有的句柄、锁及能证明归属的未发布临时资源 | 扫描修复旧环境、删除用户数据、恢复旧版本、清除归属不明的锁 |
| 用户备份 | 删除产品恢复能力，不删除用户已有备份、快照和数据 | 为证明功能已移除而删除用户资产 |

安装命令内部的包管理器行为、第三方插件自己的行为和操作系统行为，不在 Spaces 可控承诺之外被一并保证。验收测量 Spaces 自己发起的调用和它控制的路径。

## 文档与代码分别验收

**文档完成：** 所有有效说明、计划、任务和验收不再要求恢复；历史事实保留；后续代码差距清楚。

**代码完成：** 错误处理、任务状态、Supervisor、Doctor、升级流程、UI、API、CLI 和构建里，都不存在替用户恢复的可达执行链，并通过真实故障验收。在那之前，不得声明“运行时已符合 let it crash”。

最终判断标准：

> 它可以失败，可以崩溃，可以保持坏掉。我们把已知原因说清楚，但不替用户把它救回来。
