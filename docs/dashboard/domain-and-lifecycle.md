# 数据模型、并发与生命周期

状态：设计合同，待实现。字段定义：[contracts.ts](contracts.ts)。接口：[api.md](api.md)。

## 1. 三种对象

组件类型由 provider 声明：`typeId + version` 确定数据/渲染合同。组件实例由来源空间持有：`spaceId + providerId + instanceId` 是 Home 内的完整身份。摆放记录由看板持有：引用实例、位置和尺寸；没有业务任务副本。

跨 Home 引用首版不支持；同一 backend 返回的 ref 不得交给另一个 backend 使用。`spaceId` 沿用宿主稳定身份而非显示名；新建/克隆空间获得新身份。`providerId` 由 Host 绑定到实际插件身份；`instanceId` 由该插件稳定保存，不以标题生成。所有 ID 都是数据，不是文件路径。

类型版本与看板协议版本独立。v1 只接受 progress、metric、list、markdown 四种内置内容；同一 type 的声明 kind 必须与实例 content.kind 一致。未知类型或版本显示“不支持”，不得猜测解释或运行网络脚本。

## 2. 来源快照

每个 provider 一次发布完整的、已获授权的类型和实例集合，不发数据库 patch 或工具执行事件。一个请求内先验证全部字段、引用、配额与授权，再原子替换该 provider 的投影。任一实例非法则整份快照失败；不得跳过坏项并返回成功。

当前快照缺少上次存在的实例，表示该授权范围内的实例已移除。它不删除源任务；已有摆放变成来源不可用占位。获取源数据失败不得伪装成空快照。授权撤销与正常移除不同：撤销后连旧内容和标题也不再提供。

每个正常启动的空间发布会话获得 Supervisor 绑定的 `runId`。每个 provider 的 sequence 从 1 开始增长；同一 run 内完整快照可以跳号，不能倒退。只允许一个在途发布请求；未发送的高频变化可以合并成最新完整快照，但失败后不得继续排空或补传。

| 输入 | 处理 |
| --- | --- |
| 当前 run，sequence 大于已接受值 | 验证并提交完整快照 |
| 相同 run/sequence，内容完全相同 | 返回原确认，不重复写入或更新 receivedAt |
| 相同 run/sequence，内容不同 | `dashboard/sequence-conflict` |
| sequence 小于已接受值 | `dashboard/stale-sequence` |
| 非当前 run、旧授权 revision 或旧凭据 | 拒绝；旧进程不能覆盖新进程 |

等同内容按服务端规范化后的严格 JSON 值比较：对象键排序、数组顺序保留、有限数值、禁止重复键。不是以源时间戳排序，也不是使用管理 `expectedRevision`。不同 provider 之间没有全局事务或共同 sequence；同批查询可以包含不同来源各自的已提交版本。run 的新旧只能由 Supervisor 的当前空间实例身份确认，不能相信客户端自报时间。

## 3. 状态必须分开

业务状态由内容表达，例如 running/waiting/succeeded；进程状态由 Supervisor 观察；数据是否过时由接收时间与已确认的通道状态决定。三者不能互相代替。

`receivedAt` 为聚合层首次提交该序列的时间，`updatedAt` 为 provider 声明的业务更新时间。心跳只证明发布通道仍有活动，不修改业务更新时间、不延长数据 freshness。`staleAfterSeconds=null` 只适用于明确的静态结果；来源断开、失败或停止时仍显示离线/失败标签。

客户端使用服务端返回的 freshness；本地时钟只负责展示相对时间。缓存中的“任务运行中”不等于当前任务确实仍在运行。停机后可以显示“最后记录：运行中”，不能显示新的虚构进度。

## 4. 故障状态机

发布会话：`local-only` 或 `starting → active → failed/closed`。failed 在本次会话内是终态。启动注册、首次 grant 读取或发布失败均停止相应通道；正常配置后的一次用户启动可建立新会话并读取当前快照，但不重放旧事件或中断任务。

看板读取会话：`opening → active → failed/closed`。默认 2 秒一次，只在上次读取成功后继续；单次超时 5 秒，无并行堆积。HTTP 错误、超时、解码/版本失败都会结束会话。用户重新打开/刷新页面是新的只读会话，不是重试业务操作；错误卡片只提供诊断，不添加“恢复连接”按钮。

空间进程停止时，其余空间继续工作；发布插件出错但 Host 存活时，不主动杀掉 Host。DashboardHub 模块内部发生局部操作错误，应返回真实错误；不能偷偷切换存储实现或把损坏文件当成空看板。认证失效需要立即隐藏敏感卡片，不保留“离线缓存”绕过权限。

Supervisor 重启意味着旧 run 授权全部失效。仍存活的旧子进程不自动接入新服务。新用户启动按仓库已有归属检查执行；不得为看板增加接管旧子进程逻辑。

## 5. 布局 CAS 与幂等

每个看板有自己的 opaque revision。replace/delete 必须提交读到的 expectedRevision；冲突返回 409，不自动合并或覆盖。不同看板可独立修改；两个窗口修改同一看板时最多一个成功。来源进度更新不改变布局 revision，也不导致管理配置无关冲突。

创建使用调用方生成并在首次请求前保存的唯一 boardId，已删除 ID 不复用。默认看板使用 backend 提供的稳定 defaultBoardId。每次变更包含 requestId、issuedAt 和 backendEpoch。已知相同 requestId/主体/内容返回原结果；同 ID 不同内容冲突；未见过且 issuedAt 距服务器时间超过 5 分钟的写入拒绝。

布局与对应回执必须在同一原子提交中持久化。回执保存至少 24 小时；容量满时拒绝新写入，不提前驱逐仍在保证期的回执。删除保留 boardId tombstone。回执过期不保证可读回原结果，但旧 issuedAt、布局 CAS 和 ID 不复用仍阻止重执行。

请求超时后客户端不重发，允许独立查询 requestId 的回执。查不到不证明没有产生影响；显示“结果无法确认”，不能自动创建新 requestId 执行同一意图。

## 6. 存储所有权

home 模式建议在 `<Home>/.spaces-dashboard/v1/` 下新增专用目录；这是拟新增路径，不是当前既有存储。布局和回执放入同一原子文档；每个 provider 的投影与 run/sequence/digest 放入同一个原子文档；授权策略独立保存并由唯一 Supervisor 写入。文件名使用服务端映射的安全 ID/hash，不直接拼接用户输入。

local 模式使用当前命名空间的官方存储能力，由本 Host 单写入，不扫描 Home。具体官方存储适配在 P0 验证。不修改根默认 sessions/storages，不把 source 的业务数据迁移进看板目录。

写入采用同卷临时文件、完整验证、原子 rename，成功确认在耐久提交之后发送。提交前失败不替换旧文件；提交后故障留证，不回滚。需要证明崩溃一致性与平台 flush 行为，不能以使用 rename 单独宣称断电持久性。

损坏或未知存储版本明确失败，不自动从快照重建；读取留存的合法展示投影不等于恢复业务。Hub 已正常打开且用户正常启动一个 provider 后提交当前快照，是新的发布，不是 replay。

## 7. 删除、停用与权限变更

| 操作 | 结果 |
| --- | --- |
| 移除摆放或删除看板 | 仅改布局，不停止任务、不删除实例 |
| 来源插件正常移除实例 | 更新投影，保留无敏感内容的失效引用 |
| 停止空间 | 保留获准的最后投影并标离线；不自动启动 |
| 撤销发布授权 | 先提交拒绝读取的策略，再使凭据/缓存失效并清除该授权内容 |
| 卸载看板/provider | 停止相应展示/发布；原业务数据保持原样 |
| 删除空间 | 先阻断其读取和发布，再处理投影及原有空间删除流程 |

撤销后的访问检查必须优先于缓存读取。若物理清除失败，撤销仍保持有效，操作记录清除失败，不恢复旧授权、不报告“已彻底删除”。已有用户备份不自动删除，撤销不承诺抹除历史备份或对方已看到的数据。

## 8. 首版资源边界

以下是设计默认值，不是已测性能：每空间最多 32 个 provider；所有 HTTP 请求 body 最多 1 MiB、响应编码最多 8 MiB；布局/回执文档最多 32 MiB、有效回执最多 10,000 条、累计 boardId（含删除 tombstone）最多 10,000 个；每 provider 最多 32 种类型、100 个实例；单实例 content JSON 最多 32 KiB；发布 body 最多 1 MiB；每次读取最多 50 个 ref；Home 最多 5,000 个实例、64 MiB 有效投影；最多 20 个看板、每看板 200 个摆放。进度最多每 provider 每秒发布一次，心跳 15 秒一次；单 publisher 所有请求总计最多每秒 5 次。

限制在接收前执行；超限拒绝，不截断、不静默丢卡。调度器在首次发送前做合并/公平排队；已失败请求绝不因限流再次排队。过期回执只在正常写入准备时按保留策略清理，不重放原请求；累计 ID 上限不通过复用已删 ID 绕过。客户端使用 overview 返回的实际 limits；改变限额须同步合同、边界测试和说明。

目录分页默认 50、最大 100。cursor 绑定 backendEpoch、主体、过滤器和 catalog 元数据 revision；只更新内容不改变该 revision。过期或目录结构改变返回 cursor-invalid，不暗中从第一页继续。每页重新校验授权；不可通过旧 cursor 获取撤销的数据。
