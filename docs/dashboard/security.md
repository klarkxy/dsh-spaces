# 发布权限与安全边界

状态：设计合同，待实现。授权接口见 [api.md](api.md)。本文约束不取代 [现有故障政策](../let-it-crash.md) 和 Home 单写者边界。

## 1. 主体与最小权限

| 主体 | 可以做 | 不可以做 |
| --- | --- | --- |
| business provider | 本 Host 注册自己的组件 | 声明其它空间/插件身份、获得 Home 管理 bearer |
| run publisher | 输出绑定空间的获准 provider 快照 | 读其它空间、改布局、启动进程、改发布授权 |
| dashboard reader | 读取当前授权投影与布局 | 发布源数据、改变权限或执行任务 |
| layout writer | reader 能力加布局 CAS | 修改源业务状态、跨越授权读取内容 |
| Home manager | 现有管理能力与发布授权预览/执行 | 绕过现有 epoch/revision、锁、维护和审批边界 |

这是服务边界，不是 Node 插件沙箱。同 Host 中不可信代码、同一 OS 用户的恶意进程可能读取其他插件内存或文件；仅把 bearer 限定到 spaceId 不能解决这一层攻击。本版不宣传插件级强隔离、多用户租户隔离或对机器管理员保密。

Supervisor 不导入业务插件代码，只执行本产品的固定验证、存储和授权逻辑。Home 级汇总可见不代表空间 A 的 Agent 可读空间 B 的数据；跨空间 Agent 读取需要另行设计能力授权，首版不提供。

## 2. 默认与同意

新增空间默认具备 provider 基础能力，但业务发布默认关闭。Supervisor 已知的空间名称与运行状态可以显示在已有管理界面权限内；会话内容、Dream 记忆、词汇解释、代码、文件内容和生成结果不会因为安装 provider 自动导出。

发布单位为 provider 的选定实例或用户明确选择的 all。all 包含未来新增实例，必须显式说明。标题、列表文字和 Markdown 同样可能包含敏感信息，不能称为“只是元数据所以无需授权”。Schema 只能限制结构，不能保证用户文本中没有密钥；作者需要最小化内容，用户需要看清范围。

不设置默认云端出口；首版 Home 发布仅到绑定 loopback 服务。未来的外部同步或远程 Home 需要独立出口配置和授权，不沿用本地发布同意。

## 3. 凭据交付

拟用 `DSH_SPACES_DASHBOARD_BOOTSTRAP_FILE` 向受管理 Host 传递私有 bootstrap 文件的位置，而不是在命令行、URL、HTML 或前端全局变量中携带 token。文件由 Supervisor 在正常启动空间前创建，只包含当前 run 的 loopback endpoint、runId 和最小发布凭据；路径和 bearer 不进入任何浏览器 DTO。

POSIX 文件权限仅所有者读写；Windows 必须实现并验证仅预期用户/服务身份访问的 ACL，不能拿 chmod 数字当 Windows ACL 的证明。打开时检查普通文件、符号链接/reparse point、归属和规范路径。无法建立约束就拒绝启用该发布通道，不降级为命令行明文 token。

凭据绑定 Home、空间实例代次与 runId；服务更换或空间正常停止时失效。发布端只接受 bootstrap 中经过校验的 loopback origin，HTTP 禁止自动跟随重定向，超时 5 秒、无自动重试。不存在 bootstrap 配置时不扫描 Home 寻找凭据。

管理 bearer、发布 bearer、视图 correlation channel 是不同用途，不能互换。全量 dump-config、诊断、异常栈、安装预览和子进程日志均不得输出 bootstrap 内容。临时凭据清理只能针对能证明归属的本次 run；不能为清理凭据扫描/修复未知历史环境。

## 4. 授权检查顺序

发布：检查监听地址和主体 → 校验当前 run → 绑定真实 spaceId → 检查 provider 与 grant revision → 检查请求大小和严格 JSON → 检查类型/实例/选择范围 → 检查序列及配额 → 原子提交 → 确认。

在最终提交发布或构造读取响应时，必须在受控临界区再次核对当前授权 revision，避免校验期间已撤销却仍接受新写入或构造新响应。已经发出的响应字节不能撤回。

实现上必须在 JSON 完整解析前先施加 body 字节上限；上面的业务检查顺序不能成为无限读取 body 的理由。认证失败不返回来源详情。

读取：认证并确定 backend → 读取当前授权策略 → 限定可见 ref → 读取缓存 → 构造脱敏响应。cursor、旧 board ref、旧 receipt、导航请求都不能跳过当前授权。来源空间以外的身份不可由请求字段决定。

## 5. 撤销与删除

撤销先使策略不可读，再废止旧授权 revision，再使查询索引/内存缓存失效并删除对应活动投影；后续查询永远先检查已提交策略。清除磁盘失败保留拒绝访问状态并报告失败，不回滚授权。空间删除使用同样的阻断顺序，并遵守原有空间数据删除选项。

在线客户端下一次成功读取后应清除已撤销内容。401/403 立即清除敏感显示。网络中断时不能保证远端浏览器立即擦除已收到的信息：v1 不写业务数据到 localStorage、IndexedDB 或 Service Worker；仅保留带“连接已中断”标记的内存显示最多 60 秒，随后隐藏。合法的“源空间离线但 Hub 仍可访问”可以继续显示获准的最后结果。

撤销不撤销用户已经看到、复制或截图的信息，也不自动删除已有用户备份。备份中可能包含授权时的展示投影；预览授权/备份时需说明。本版不增加备份恢复接口。

## 6. 渲染与导航

v1 仅使用固定组件与受校验的数据。所有标题/标签按文本转义；Markdown 禁用原始 HTML、脚本、iframe、外部图片和自动网络请求。链接只允许用户主动打开的 HTTPS，并隔离 opener、提示目标；javascript/data/file 等 scheme 拒绝。单纯允许 Markdown 不等于允许任意网页组件。

SourceTarget 只有 space/session/artifact 的逻辑 ID。由可信宿主在相应空间中验证目标并执行导航，不能由业务插件提交 file 路径、含 token 的 URL 或任意 deep link。来源未运行时返回不可用，不利用导航触发启动。

移除组件、点击任务标题和查询状态都不能执行来源任务。未来 action API 必须另有能力声明、用户确认、来源端再次授权、请求去重和结果不明处理；不得复用 layout writer 权限。

## 7. 拒绝服务与故障半径

每空间发布队列、每 provider 内容大小、Home 配额和查询并发必须有界。坏 provider 的格式/尺寸错误只影响其发布，单个空间退出不连带停止其他空间。Home 存储故障需要如实报错，但不能为了收集更多诊断自动重启、修复或替换存储。

审计仅记录时间、操作类别、脱敏主体、ID、序列和结果码，不记录正文、请求 body、完整 URL 或凭据。错误不能把最近安装的插件自动归因为故障源；归属不明就明确未知。

必须测试 cookie 跨端口攻击、错 run、伪造 spaceId、旧凭据、重放旧序列、撤销后读旧 cursor/receipt、symlink/Windows reparse point 和大 body；不能只测试正常页面隐藏了按钮。
