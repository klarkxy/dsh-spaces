# 施工分解、迁移与验收

状态：**所有运行时阶段待施工、待验收**。本文件是实施计划；实际进度与证据只记入 [tasks/todo.md](../../tasks/todo.md)，不得把本文清单的存在当成实现完成。

## 1. 工作包与依赖

| 阶段 | 可独立审阅的交付物 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 合同与 SDK 探针 | 运行时 validators、DSH 可选服务/释放钩子、共享 React、local 认证及 Home 代理、bootstrap 凭据交付探针 | 隔离命名 profile 真正运行；无同名 API 猜测；明确 Windows ACL 与组件清单过渡 |

| P2 Home 数据闭环 | Supervisor 内 DashboardHub、授权管理计划、run 绑定、完整快照、配额与故障终止 | 两个未打开前端的空间同时发布；读取不启动空间；授权撤销立即阻断 |
| P3 真正首页 | 复用 DashboardView 的工作台首页、来源导航、添加/摆放/移除、双端同步读取 | 浏览器与桌面同板 CAS；旧聊天草稿保留；空/停用/失败状态真实 |
| P4 组合与业务验收 | 写作/任务两个参考 provider、选定实例授权、重复摆放、兼容状态 | 删摆放不删任务；失效来源不拖垮其他组件；无跨空间 Agent 读权限 |
| P5 安装和发行门槛 | 组件组、标准插件安装、新旧空间显式迁移、升级路径、真实双端与打包验收 | 下方验收矩阵全部有证据或明确阻断；未通过的必需平台不宣称支持 |

P1 可以在 P0 接口冻结后与 P2 的纯域验证并行；共享字段、错误、scope 变更需同 PR 更新所有合同。不能先写前端假数据，再以“界面完成”认定 P2 完成。

## 2. 当前基线的具体接入点

- 在 [WorkbenchApp](../../packages/plugin/src/workbench/app.tsx) 装配共享看板 UI，不增加 Electron 业务后端。
- 在 [workbench-supervisor.ts](../../src/adapters/node/workbench-supervisor.ts) 的既有生命周期内装配 Hub；复用 Home 所有权、维护与日志边界。
- 在 [workbench.ts](../../src/shared/workbench.ts) 及所有对应 host/client 校验器中增加发布授权 plan，维持管理协议 v2。
- 现有 [view-bridge](../../packages/view-bridge/src/index.ts) 不承担数据发布；新增 provider 独立安装和版本管理。

新 SDK 文件应从 [contracts.ts](contracts.ts) 派生，并为 JSON、跨字段关系和配额实现运行时校验。文档合同从未执行危险操作，也不意味着已经有可调用的服务。

## 3. 默认安装与旧空间

新建受管理普通空间：创建预览明确包含 provider 基础层；安装同组精确版本；默认不发布业务内容。用户拒绝发布不影响原空间工作。普通空间不得因此安装完整管理器。

已有空间：用户在正常管理设置中选择安装目标，走现有 preview/execute；不因打开首页、读取 catalog、切换主题而写 profile。正在运行的目标先依正常管理计划停下，安装后保持停止，下一次启动由用户发起。批量 A 成功/B 失败/C 未执行，保留 A 和失败证据，不继续、不回滚、不自动再安装 B。

根 `web` 不在默认迁移目标中，管理 profile 不被普通空间安装规则覆盖。测试只使用沙箱命名 profile，不能为了独立插件验收改真实 `profiles/web` 或根会话/存储目录。

首页旧聊天视图保留独立入口和原有会话/草稿；不搬聊天数据到看板目录。首次创建默认空布局是显式 mutation，不由 GET/query 写入。

## 4. 不可变组件清单的过渡

基线 [component-payload.ts](../../src/adapters/node/component-payload.ts) 的 schemaVersion=2，组件集合严格为 supervisor、manager-plugin、view-bridge、llm-bridge、installation-worker。新增 provider 不能假定老解析器会接受第六个成员。

施工选定如下过渡，属于发布前工作，不是本 PR 执行升级：

1. 兼容准备构建仍输出合法五组件 schema v2，但解析/复制/验证/候选升级链显式支持新的六组件 schema v3。所有旧 v2 fixture 保持原语义，未知版本仍拒绝。
2. 新功能构建输出 schema v3，新增 dashboard-provider 的独立身份、入口、精确版本与文件摘要。dashboard UI/合同代码包含在相应已声明制品摘要内；独立 dashboard tarball另做标准安装验收。
3. 现有只识别 v2 的安装先经用户正常升级到兼容准备构建，再明确升级功能构建；不自动串行升级或失败后改用其他版本。新安装可直接采用完整 v3 组。未经这条真实路径验证，不开放旧版的一键直升入口。

组件清单 schema v3 与管理协议 v2、看板协议 v1 不同，不要把组件的 protocolVersion 跟随 schema 一起盲目加一。准备构建和功能构建的具体发行版本应在发布审批时指定，本设计不虚构已存在的兼容版本。

需要同步构建、打包、supervisor-pack、冷启动、安装 worker、组件复制/摘要、候选预览、一次性交接和桌面 payload 的消费端。缺失 provider 制品必须在提交前拒绝，不允许运行时联网补一个 latest。标准插件和桌面必须消费同一经过验证的组。

## 5. 蓝图边界

蓝图 v1 只创建新的普通 Web 空间，插件配置可以声明该空间的静态组件预设，但不能携带 Home 凭据、spaceId、runId 或自动发布同意。生成蓝图时过滤接收者本机 ID 和授权状态；应用后需接收者重新选择发布范围。

基线的 extensions 不增加执行行为。不要通过它配置全局布局、申请 Home 权限或安装全局插件；全局布局分享格式和多空间方案另立合同，不在首版悄悄扩展 BLUEPRINT.md。

## 6. 验收矩阵

所有条目当前均为待验证。测试应记录构建 SHA、DSH 精确版本、OS、运行模式、执行步骤、断言和脱敏证据路径。

| ID | 场景与必须成立的断言 |
| --- | --- |
| D01 | 独立 DSH Web 中 provider+dashboard 可用；没有 Supervisor/Electron；local 接口不能读取其它 profile |
| D02 | 业务插件未安装看板能力仍完成原业务；关闭 Home 发布不影响本地业务 |
| D03 | 两个空间只开 Host、不打开 iframe，交错发布后同一 Home 看板都更新 |
| D04 | 停止一个空间，保留有明确离线标签的获准投影；其它空间继续更新；query 的 spawn 调用计数为零 |
| D05 | 浏览器/桌面看到同一布局；退出桌面后后台继续；两个窗口同 revision 修改只有一个成功 |
| D06 | 来源进度更新不改变 board revision，也不改变无关管理 CAS；不同看板可独立写 |
| D07 | 首次 seq=1、跳号全量快照、旧 seq、同 seq 同内容、同 seq 异内容、新 run 后旧 run 均符合合同 |
| D08 | 单实例非法时整份 provider 快照不提交；不能返回空集合或部分成功；其他 provider 不被主动停止 |
| D09 | 发送成功后确认丢失：发布端不重发；布局超时只查 receipt，不自动再次执行；未知结果如实显示 |
| D10 | 浏览器读失败、发布超时、429、401、协议错误后，定时器/网络调用计数不再增长；没有自动重连、补传或重启 |
| D11 | 同实例放入两个看板；删除一处/删除看板不删除实例或停止任务；来源移除显示失效占位 |
| D12 | 撤销时来源可以离线；旧 bearer/grant、catalog cursor、board ref、receipt 和导航都读不到撤销内容 |
| D13 | 伪造 spaceId/providerId/runId，workspace/view 凭据调管理端点，publisher 调布局端点均被服务端拒绝 |
| D14 | 跨端口 Cookie/CORS/Origin、超大 body、重复键、未知字段、路径穿越、symlink/reparse point 均有负例 |
| D15 | Markdown 的 script/iframe/远程图片/file URL 不执行或请求；打开来源不触发业务写入/自动启动 |
| D16 | 磁盘提交前失败保留旧文件，提交后失败不回滚；损坏布局/未知 schema 不被替换为空值 |
| D17 | 新空间预装透明、旧空间显式安装、默认 web 指纹不变；批量失败后剩余目标没有调用 |
| D18 | 旧管理聊天历史与草稿保留；空首页有可用入口；窄屏、键盘移动/缩放/关闭、焦点返回和双语文案通过 |
| D19 | schema v2 到准备构建到 v3 功能构建真实完成；缺制品/错摘要/混组明确拒绝，无自动换版 |
| D20 | 浏览器认证失效隐藏内容；网络中断内存显示最多 60 秒；不写业务正文到浏览器持久存储 |
| D21 | 至少 20 个空间、共 1,000 个实例、两个客户端持续运行 30 分钟；记录查询 p95、投影延迟、CPU/RSS/磁盘增长与请求数 |
| D22 | 在第 1 MiB/32 KiB/50 refs/100 instances 等边界两侧测试，拒绝超限且无截断；热源不能饿死其他来源 |

D21 是拟定测试负载，不是已测性能。目标在规定测试硬件上：正常本地查询 p95 不高于 500ms、业务提交至可见投影 p95 不高于 5 秒；内存/队列在配额内有界且无持续无界增长。必须在证据中记录硬件和实际结果，不能将这些目标当宣传数字。

## 7. 施工记录与发布门槛

每个实现 PR 同时更新合同差异、对应 Dxx 证据与未测项。协议、权限或故障规则变化需要显式设计修订，不允许一个实现分支私自扩大 scope。P0 验证失败的 SDK/ACL/升级路径是对应能力的阻断项，不靠 mock 通过代替。

首版发布前必须有真实标准插件、Windows 桌面与 Chromium 双端、停止/离线/撤销/故障注入和旧版组件过渡证据。其他 OS 未实测应明确标注，不继承仓库历史版本的验收结论。文档编译、单元测试、CLI 集成、浏览器验收、打包程序验收分别记录。

任何阶段都不修改真实 `~/.dsh`，不增加自动/手动恢复入口、不自动重试中断安装、不重放任务。本次文档 PR 不包含运行时迁移、发布或合并授权以外的操作。
