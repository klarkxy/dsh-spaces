# @dsh-spaces/browser

Browser is a separate DSH Space plugin. It owns one blank home tab at startup and opens an HTTP(S) URL in a new tab through `browser.openURL`; `browser.listTabs` lists tabs. The total limit is 16, including Home. This MVP has no close-tab command and no restore across Space restarts. The DSH client root is replaced with the Browser UI rather than embedding the chat page. It reuses the official DSH Web Host, Cordis, authenticated Connection RPC and slot renderer; the independent root, small tab state and cross-Space operations are local implementations. It does not directly extract the official Session-sidebar Browser component. The package has no model integration, Playwright bridge, DOM extraction, or content access.

The Browser Host requires a Supervisor-owned Space with the lightweight view bridge and private Node IPC. A plain `dsh web` profile launched outside that ownership does not supply `spaceMessages` and will not activate the Browser Host. The Space's `cordis.patch.yml` must explicitly name allowed source Space IDs in `config.allowedSpaces`; the default empty list denies all cross-Space callers. The Host-only `spaceMessages` service performs caller authentication and checks the exact source allowlist on every operation. Static capability descriptions are filtered by the same allowlist. The Browser UI uses DSH's authenticated same-Space Remote. Tabs live only for the current Space process lifetime.

To permit a Space named `coding` to call this Browser Space, edit the Browser Space's own `cordis.patch.yml` Browser row while it is stopped and replace the entire config with `config: { allowedSpaces: [coding] }`, then start it. Do not set a wildcard or copy the manager's plugin into the Browser Space. The source Space must already have the lightweight view bridge so its Host can use `ctx.spaceMessages.request('browser-space-id', 'browser.openURL', { url: 'https://example.com' })` and `ctx.spaceMessages.capabilities('browser-space-id')`. Permission changes take effect only after the Browser Space starts with the new config. No all-Spaces grant exists.

`requestedUrl` is the address used when a tab is opened. In Web mode, each page is an iframe. Sites may block embedding, and cross-origin links and redirects inside the iframe are not observable by the Browser Space. Therefore `url` and the address shown in Web mode remain the opening address, not necessarily the iframe's current page. The UI labels this as a Web preview and explains that some sites refuse embedding, with an explicit external-open route for blank or refused pages. This is a visible limitation notice, not automatic detection of a cross-origin failure cause. No claim is made that arbitrary websites can be displayed or that Web mode can read their content.

The desktop candidate uses shell-owned, sandboxed guests without a privileged guest preload or nested webview tags. Ordinary A/B/A tab switching keeps the native guests. After the Browser view is hidden or another Space is selected, the short presentation lease expires in roughly 2.5 seconds and can destroy the guests and temporary session, so tab contents and sign-in state are not promised to survive a long absence. Desktop GUI behavior needs local acceptance. Installation and test instructions are in the repository's main documentation.
