# @dsh-spaces/llm-bridge

普通空间内的 LLM 接入组件。它做三件事，并把三种模型来源分开：

| 来源 | 由谁提供连接与凭据 | 调用是否离开本空间 |
|---|---|---|
| 主空间继承 | 主空间官方服务 | 是，经 Supervisor 委派通道 |
| 旧共享连接 | Home 级共享连接库 | 否，由本空间官方 adapter 直连供应商 |
| 本地连接与会话选择 | 本空间自己的配置 | 否 |

## 主空间继承

新建普通空间默认跟随主空间模型，不需要在子空间创建共享连接或填写凭据。

- 主空间拥有官方调用准备、adapter 与供应商凭据；本组件不复制任何 provider 配置或 Key。
- 显示为两类路由：跟随主空间当前默认，以及主空间下具名的模型。跟随意味着每次模型调用准备时读取主空间当前默认；已准备好的调用保持冻结目标。
- 显式控制参数（推理等级、温度、最大输出等）在请求冻结前确定；选择默认不会顺手抹掉已显式选定的推理等级。
- 完整转发流式结果，包括工具、推理、用量、终止原因与不透明 replay 状态。断流保留部分输出，不补造成功。
- 零自动重试。取消由委派通道承担，消费方结束、来源退出或主空间退出都要释放资源。
- replay 保留原生响应状态与真实的上游路由，重新打开会话时可以分辨历史来自主空间；本地历史中同名 provider 不能证明主空间来源。
- 附件与来源会话的授权、路径与完整性检查发生在文件被投影或图像被读取之前。
- 被中断的调用失败并释放资源。没有重试、重连、备用来源或中断任务续跑。

继承以主空间存活为前提。主空间或 Supervisor 退出时该路径失败，本组件不自动启动主空间、不改读配置，也不切换到其他来源。

## 旧共享连接

旧共享策略继续支持，语义保持不变：

- 把本空间选中的共享连接合并进官方模型适配配置的受管层，空间的原始配置与 patch 保持本地唯一；
- 从全局凭据存储解析共享凭据引用；
- 拒绝针对受管路由的官方设置、配置编辑与凭据写入；
- 报告连接来源，以及本空间启动时使用的目录与策略版本。

本组件不安装插件、不启动第二个 Supervisor、不操作其他空间。共享路由不写入空间 profile patch。完整契约见[旧共享连接兼容合同](../../docs/plans/global-llm-connections.md)。

旧共享路径的进程输入是启动时冻结的快照；缺失所需的官方模型适配器会被报告，不会静默安装。退出共享接入或卸载本组件，不删除 Home 级连接目录与凭据。

## 共同约定

- 官方 SDK 是固定外部依赖，本组件不修改它。
- 模型正文只在主空间继承路径上经过 Supervisor；另外两条路径由本空间官方 adapter 直连供应商。
- 本组件不创建第二套会话、Agent、存储或管理器。
- 故障政策：[let it crash](../../docs/let-it-crash.md)。当前数据面与所有权：[现行架构](../../docs/architecture.md#6-llm-数据面)。
